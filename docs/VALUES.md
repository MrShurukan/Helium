# Значения, Copy/Clone и ограниченные ссылки

Контракт согласован 28 октября 2026. Первым этапом добавлены реестр и move-анализ.
Следующим этапом реализованы фиксированные scalar-массивы и временные ссылки на них:
[ARRAYS.md](ARRAYS.md). Временные слайсы и `.clone()` scalar-массивов/Copy-значений
также реализованы. Структуры, общие `&T` и сохраняемые ссылки пока не поддержаны.

## Принятая семантика

| Категория | Передача значения | Временный доступ |
| --- | --- | --- |
| Числа, bool, PinState | Copy | Обычно по значению |
| Читающая ссылка, включая &str | Copy ссылки, не содержимого | С ограничениями исходного заимствования |
| Фиксированный массив, будущий String<N> | Move | &T / &mut T |
| Изменяющая ссылка | Move, без Copy/Clone | Повторное временное заимствование при передаче helper |
| Hardware-wrapper | Исключительное владение, без Copy/Clone | Контракт доступа к устройству отдельно |

Массив не получает Copy даже при Copy-элементах. Его Clone может быть структурным.
Пользовательская структура по умолчанию передаётся по владению; явный Copy возможен
лишь при допустимости всех полей. Будущий синтаксис меток/реализаций не выбран.

Move применяется при инициализации, присваивании, передаче аргумента по значению
и возврате. После него исходное значение недоступно. Полное присваивание нового
значения восстанавливает доступ; правая часть вычисляется до изменения назначения.
Это семантика владения, а не обещание отсутствия машинного переноса байтов/стека.
Аллокатор для неё не нужен. Глобального владельца нельзя переместить из хранилища:
для работы с ним нужны заимствования, включая проверку доступа из ISR.

Если присваивание используется как значение, результат передаётся из назначения:
`var b = (a = c)` перемещает c в a, затем a в b; доступным остаётся b.
Самостоятельное `a = c;` оставляет a доступным. Обычное чтение через имя, без
передачи значения, всё равно проверяет, не было ли оно ранее перемещено.

На объединении веток значение доступно только если доступно на каждой входящей
ветке. Ветка с return не входит в последующее объединение. В циклах учитывается
обратное ребро: передача владельца без восстановления недопустима уже для второй
итерации. Новая локальная декларация создаёт доступное значение на каждой итерации.
Условные выражения и and/or сохраняют альтернативные пути и порядок вычисления.
Анализ структурный: константные условия не устраняют ветки, специального доказательства
«этот цикл исполнится ровно один раз» пока нет. For проверяется в AST, но по-прежнему
не поддерживается машинным backend.

Неинициализированные значения и частичная инициализация не разрешаются этим этапом.
Существующая инициализация скаляров по умолчанию сохранена. Правила полной инициализации
элементов и формы литералов массива реализованы и описаны в ARRAYS.md.

## Заимствования: реализованное временное подмножество

* Несколько читающих заимствований допустимы; пока они используются, изменение
  соответствующих данных через другое имя запрещено, включая код вне ISR.
* Изменяющее заимствование эксклюзивно относительно других чтений и записей.
* Первый этап — синхронная передача и повторное заимствование через helpers.
  Сохранение/возврат ссылок, поля со ссылками и общий синтаксис lifetimes позже.
* Вначале заимствуется весь массив, без доказательства непересечения диапазонов.
* Проверять доступ через глобальные имена, транзитивные helpers и ISR.
  &mut не выключает IRQ, а noInterrupt не разрешает конфликтующие ссылки.

Копирование читающей ссылки не завершает и не ослабляет исходное заимствование.
Для временных ссылок на массивы эти правила проверяет отдельный loans-проход;
проверка move его не заменяет. Общие сохраняемые ссылки остаются будущим этапом.

## Реализованный фундамент

`src/values.rs` содержит реестр контрактов типов. TypeId принадлежит одному реестру;
это идентичность контракта значения, не новое runtime-представление и не замена всей
системы типов. Records в реестре — метаданные для будущих структур, не разрешение их source-синтаксиса.
Scalar-массивы уже имеют source-типы и машинную реализацию по ARRAYS.md.

Реализации привязаны к `(TypeId, Capability)`; Copy и Clone — первые встроенные
контракты. `Registry::implement` — общий проверяемый вход для встроенной,
структурно генерируемой и будущей пользовательской реализации:

* Copy не выполняет пользовательский код; требует Clone и Copy всех полей.
* Структурный Clone требует Clone каждого поля/элемента.
* Пользовательский Clone представлен идентичностью реализации и разрешённой
  сигнатурой `clone(&Self) -> Self`, без дополнительных аргументов.
* Нельзя регистрировать повторную реализацию, несовместимую сигнатуру или
  Copy/Clone для владельца hardware либо содержащего его контейнера.
* На этом этапе контейнеры с эксклюзивной ссылкой также не клонируются.
* Неудачная регистрация не меняет реестр.

Будущий frontend меток должен разрешить реальную сигнатуру функции и её identity,
затем вызвать этот же API. Одного заявления пользователя о сигнатуре недостаточно.
Вызов встроенного Clone скаляров/читающих ссылок и Structural Clone scalar-массивов
реализован через этот реестр (ARRAYS.md). Для будущих структур и Function-реализаций
пока проверяются метаданные: генерация тела, связь с таблицей функций и перенос
эффектов пользовательского Clone в граф вызовов ещё не добавлены.
Backend не распознаёт строку "clone". Полная система traits, generic bounds,
associated types и динамическая диспетчеризация не реализованы и не обязательны здесь.

`Contracts::resolved` связывает реестр с SymbolId и проверяет полноту отображения;
`AnalyzedProgram::value_contracts()` открывает неизменяемый результат. Текущий frontend
использует адаптер StaticType. Пользовательские типы смогут передавать своё отображение,
не меняя правил анализа владения.

`src/middle_end/ownership.rs` проверяет resolved AST после типизации, до shared/effects
и до IR/оптимизаций. Состояние по SymbolId хранит возможное перемещение и место причины.
На циклах вычисляется неподвижная точка, на return прекращается текущий путь.
Диагностика E_OWNERSHIP показывает использование и связанное место передачи владения.
Решение Copy/Move берётся исключительно из реестра контрактов.

Скаляры и &str — Copy; новые FixedArray — Move. ArrayRef допускает временный reborrow
при передаче в helper. Source-проверки массивов используют этот же реестр; loans.rs
отдельно проверяет конфликты доступа. Legacy `string`/Array в StaticType по-прежнему
не проходят прежнюю границу поддержки. Статический device не является runtime-значением.

## Проверки и следующий шаг

`tests/value_contracts.rs` проверяет текущие типы, будущие маркеры структур,
ограничения полей, конфликтующие реализации и сигнатуры Clone.
Unit-тесты ownership используют реальный разобранный/разрешённый управляющий поток,
но подставляют move-only контракты выбранных символов. Это **semantic fixtures**,
не доказательство машинной поддержки массивов/структур. Тот же fixture с объявленным
Copy успешно проходит тот же анализ, без изменения алгоритма или специальных имён.

Проверяются ветвления, возвраты, short-circuit, порядок аргументов, повторная
инициализация, циклы, глобальные владельцы и независимость SymbolId от имени.
Semantic fixtures дополнены source- и машинными проверками в tests/arrays.rs.
Слайсы и исполняемый Clone массивов реализованы по ARRAYS.md. Далее — общие
временные ссылки, структуры/результаты и String/форматирование.

Форматирование должно помогать оценить байтовую ёмкость UTF-8. Динамическая память
не является частью этого этапа; fallible-копирование растущих строк требует
отдельного контракта результата, обычный Clone заранее его не определяет.

Проверка первого этапа реестра: 201 тест в debug и 201 в release, включая все
машинные сценарии; fmt и Clippy прошли. Лог: `build/value-contracts-full-gate.log`.
Новые 14 тестов проверяют реестр и ownership; AVR-прогон подтверждает отсутствие
регрессий существующего языка, но не машинную поддержку будущих owner-типов.
