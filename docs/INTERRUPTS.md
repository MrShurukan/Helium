# noInterrupt: первый этап поддержки прерываний

Реализованы защищённые блоки и явные требования функций. Timer1, обработчики ISR,
анализ общей памяти и калькулятор периодов описаны в [TIMERS.md](TIMERS.md).

## Синтаксис и смысл

```text
noInterrupt fn increment() {
    counter = counter + 1;
}

fn snapshot(): u16 {
    noInterrupt {
        return counter;
    }
}

loop {
    noInterrupt {
        increment();
    }
}
```

- `noInterrupt { ... }` сохраняет состояние разрешения прерываний, запрещает их,
  исполняет тело и восстанавливает прежнее состояние при выходе.
- `noInterrupt fn ...` только требует запрещённых прерываний от вызывающего кода.
  Модификатор сам не создаёт блок и не добавляет инструкции запрета/восстановления.
- Прямой вызов такой функции разрешён внутри блока, другой `noInterrupt fn` и `setup`.
- Обычная функция проверяется независимо от своих вызывающих функций. Если её тело
  вызывает требующую защиту функцию, нужен собственный блок или явный модификатор.
- Правила действуют для аргументов, инициализаторов, условий, return и недостижимого кода.
- Блок создаёт обычную лексическую область. Затенение по-прежнему запрещено.
- Вложенные блоки восстанавливаются в обратном порядке. `return` сначала вычисляет
  результат, затем закрывает все активные блоки этой функции.
- Return из вызываемой функции не закрывает блок вызывающей функции.
- `break`/`continue` язык пока не поддерживает; при добавлении им потребуется cleanup.

Непустой `setup` оборачивается в защиту с восстановлением исходного состояния.
Пустой setup не добавляет операций защиты. В программе с таймером прерывания
запрещены до инициализации и разрешаются после setup и настройки Timer1.
Обычный loop не считается защищённым даже если текущая прошивка ещё не включает прерывания.
Глобальные инициализаторы по-прежнему не могут вызывать функции.

## Диагностика

`E_INTERRUPT_CONTEXT` указывает на полный вызов и связывает его с точным диапазоном
модификатора `noInterrupt` в объявлении. Подсказка предлагает защищённый блок либо
явное требование у вызывающей функции. Пропущенная `{` и модификатор без `fn` —
обычные синтаксические ошибки, включая незавершённый исходник.

## IR и AVR

Функция хранит `requires_no_interrupt`. Операции `InterruptSave` и
`InterruptRestore` являются эффектами и не удаляются DCE. Сохранённое значение имеет
внутреннее представление u8, но verifier разрешает использовать его только как токен
восстановления соответствующего блока: не как обычное число, аргумент или результат.

Verifier проверяет порядок восстановления, одинаковые стеки областей на слияниях CFG,
закрытие областей на return и защищённый контекст вызовов. Интерпретатор моделирует
разрешение прерываний, но не асинхронные ISR, периферию или временные характеристики.

На ATmega328P сохранение SREG и CLI находятся в одном volatile inline-asm выражении.
Выход восстанавливает SREG. Обе границы содержат memory clobber, чтобы оптимизатор
учитывал память; чистые вычисления не обязаны оставаться внутри блока.
Принцип восстановления соответствует
[ATOMIC_RESTORESTATE в AVR-LibC](https://avrdudes.github.io/avr-libc/avr-libc-user-manual/group__util__atomic.html).

Это не обещание точного времени исполнения, остановки периферии, защиты от DMA или
других процессоров. Механизм ориентирован на текущий однопроцессорный AVR target.
Совместная с ISR память проверяется по правилам [TIMERS.md](TIMERS.md).
Volatile применяется к глобальным переменным, доступным из ISR.

## Проверка

`tests/interrupts.rs` проверяет диагностики, Unicode-диапазоны, обрезанные программы,
области видимости, контракт вызовов, обе исходные маски, вложенные блоки и ранние return,
а также испорченный IR. Машинный тест собирает и исполняет HEX в AVR8js:
none/speed/size, с оптимизациями Helium IR и без, с исходно разрешёнными и запрещёнными
прерываниями — 12 комбинаций. Он наблюдает I-бит при GPIO-записях и после возвратов,
проверяет значения результатов и использует настоящий невстроенный вызов.

```powershell
. ./tools/activate-toolchain.ps1
cargo test --locked --test interrupts -- --include-ignored
cargo test --locked --release --test interrupts -- --include-ignored
```

Тестовый harness включает прерывания только для проверки восстановления. Исходный
Helium не получает операции произвольного включения прерываний. Плата не прошивается.
Рабочий пример: `examples/no-interrupt.he`.
