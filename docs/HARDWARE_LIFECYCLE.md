# Общие аппаратные ресурсы и запуск

Реализован подготовительный этап после ревью 27 октября. Пользовательский синтаксис
Timer1 не меняется; UART TX добавлен следующим этапом (UART_API_PROPOSAL.md).

## Идентичности и резервирование

`resources::HardwareResource` различает физический пин, периферийный блок и вектор.
`Reservations` сохраняет первого владельца и возвращает его при конфликте. Source
support и timer resolution используют один реестр с исходными местами; IR verifier
независимо проверяет резервирование. Это статическое владение оборудованием,
не замена `middle_end::shared` с его чтениями/записями и контекстами исполнения.

Одиночные `Module.timer`/`interrupt_handler` удалены. Теперь есть `devices: Vec<Device>`
и `interrupts: Vec<InterruptBinding>` с DeviceId, конфигурацией, фазой запуска,
исходным местом и связью device/vector/handler. LLVM генерирует wrapper для каждой
записи таблицы; анализ volatile проходит все корни ISR. Вызовы обработчиков как
обычных функций запрещены. Повторные ресурсы/векторы/обработчики отвергаются.

DeviceConfig содержит PeriodicTimer и UartTx; target содержит Timer1 и UART0.
Наличие таблиц не объявляет поддержку второго таймера или других MCU.
Для нового устройства нужно добавить аппаратную модель, claims, проверки и emitter;
не новое независимое поле `uart_handler` и не отдельный startup wrapper.

## Фазы

`DeviceStart(DeviceId)` настраивает/запускает периферию, но не включает IRQ CPU.
`InterruptEnable` — отдельная lifecycle-операция. Нынешний Timer1 CTC сохраняет
проверенный порядок MMIO и запускается в фазе AfterSetup.

Порядок при наличии устройств:

1. Запретить IRQ CPU.
2. Выполнить initialize: глобальная память, затем GPIO.
3. Запустить устройства BeforeSetup (UART TX).
4. Выполнить setup.
5. Запустить устройства AfterSetup.
6. Включить IRQ CPU, если есть обработчики, затем повторять loop.

Чистые программы без устройств сохраняют прежний путь initialize/setup/loop.
План последовательности один для lowering и verifier; независимые тесты проверяют
конкретный порядок. Verifier дополнительно проверяет допустимость фазы конфигурации:
перенос Timer1 в BeforeSetup сейчас запрещён. Удаление, повторение, перестановка
DeviceStart/InterruptEnable и запуск из loop/helpers отвергаются.

BeforeSetup используется для UART, доступного уже из setup. Возможность
конкретного устройства работать в этой фазе должна проверяться его собственной
моделью, а не произвольным изменением enum. IRQ-driven ожидание в setup не становится
допустимым от наличия этой фазы.

## Проверки и границы

`tests/hardware_lifecycle.rs`: порядок, отдельное включение IRQ, отсутствие лишних
эффектов без устройств, 12 вариантов испорченного IR и общие аппаратные claims.
Прежние Timer1/noInterrupt/GPIO машинные тесты остаются обязательным gate.
Передаваемые параметры ресурсов и runtime reconfiguration пока не реализованы.
UART API и общие контракты вызовов добавлены следующим этапом.

На подготовительном этапе lifecycle полный gate прошёл: fmt, Clippy, 146 тестов в debug и 146 в release, включая машинные.
Контрольные HEX llvm-gpio, timer-seconds и functions-thermostat (size, 16 MHz) совпали
побайтно с состоянием до R02/lifecycle; артефакты — build/review-before и
build/review-lifecycle. На плате этот рефакторинг отдельно не проверялся.
