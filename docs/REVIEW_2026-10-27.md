# Архитектурное ревью перед UART

Дата: 27 октября 2026. Проверен `1ff1806`, ветка `codex/reliable-compiler-base`.
Исходное рабочее дерево чистое. Пользователь согласовал обзор и порядок реализации
27 октября 2026. Конкретный новый синтаксис UART/передачи ресурсов остаётся отдельным
решением. Ниже сохранён исходный результат ревью; актуальный прогресс — в DEVELOPMENT_PLAN.

## Вывод

Основа пригодна для следующего этапа. Единственный машинный backend, типизированный IR,
отдельная семантическая граница и машинные регрессии делают проект проверяемым.
Перепись компилятора не нужна. A1–A3/B1/B2/B2a/T01/B3 соответствуют описанному объёму;
это не означает завершение R02–R04 или готовность std.

Основной риск следующего этапа — повторить специальные пути Timer1 для UART:
отдельные резервирования, выбор target, запуск и проверки IRQ. Предлагается небольшая
подготовка общей модели перед UART, без одновременного введения ownership, generics,
модулей, строк и нескольких MCU.

- Прочитаны актуальные план, roadmap, handoff и контракты; проверены ключевые пути

- Физическая плата не прошивалась; удалённый CI не запускался. Исторические измерения
  платы из ATOMIC_GPIO здесь заново не подтверждались. BASIC не изменялся и не копировался.

## Подтверждённые находки

### P2: ELF-проверка не отвергает часть несогласованных размещений

Место: `src/backend/memory.rs:71–112`, `tests/memory.rs`.
Flash считается только по PT_LOAD; SHF_ALLOC-секции с адресом ниже 0x800000
не сверяются с сегментами и не проверяются на принадлежность поддерживаемому layout.
Наличие хотя бы одного файлового сегмента Flash также не требуется.

Выполненный минимальный пример: буфер ELF32 AVR на 512 байт, e_type=2, e_machine=83,
e_phoff=64, e_phentsize=32, e_phnum=1, e_shoff=128, e_shentsize=40, e_shnum=2.
Единственный program header нулевой (PT_NULL). У второй section header SHF_ALLOC=2,
sh_addr=0, sh_size=40000. Остальные поля нулевые. `from_elf` возвращает:

```text
Ok(MemoryReport { flash_extent: 0, static_sram: 0,
    flash_capacity: 32768, sram_capacity: 2048 })
```

Это искусственный несогласованный ELF, не найденная ошибка обычного результата linker.
Но обещание отвергать повреждённые/неподдерживаемые layout в MEMORY_AND_TIMING шире
реальной проверки. Не следует считать этот parser валидатором произвольного AVR ELF.

Предлагаемое исправление: задать поддерживаемый layout и проверять согласованность
ALLOC-секций и LOAD-сегментов, файловые диапазоны и границы адресных областей;
сохранить особое правило NOBITS и образа SRAM в Flash. Не заменять учёт простой суммой
размеров секций. Регрессии: отсутствующий LOAD, секция вне сегмента, обрезанное содержимое,
переход между областями; затем существующие реальные .data/.bss/.noinit в трёх режимах.
Закрыть отдельным небольшим исправлением B3 до расширения отчётов/target.

### P3: timing inventory обещает больше исходного покрытия, чем имеет

Места: `src/backend/timing.rs:6`, `src/ir/lower.rs:503–508`, MEMORY_AND_TIMING.

```text
fn helper() {}
fn dead() { return; noInterrupt { helper(); } }
loop {}
```

`compile_typed_ir` с настройками по умолчанию успешен. `timing::inventory` возвращает
только заголовок `includes unused/unreachable code`; маскирования из `dead` в нём нет.
Lowering прекращает обход после return ещё до LLVM и до необязательных IR-оптимизаций.
При `Options.optimize=true` удаляются также константно недостижимые ветви.

Это не потеря исполняемого эффекта. Ошибка — в описании полноты отчёта и различии
между исходным shared-графом и оставшимся IR. Минимальное исправление: явно написать
«инвентаризация операций, оставшихся в переданном IR; может включать неиспользуемые
функции и недостижимые ветви». Если нужен именно аудит всего исходника, строить его
по AnalyzedProgram отдельным контрактом. Для UART достаточно первого варианта.

## Что проверено и не стало находкой

- Инициализация выделена в отдельную функцию; ветвящиеся выражения не разрушают
  startup wrapper. Verifier проверяет роли и порядок, а не прежние фиксированные ID.
- noInterrupt сохраняет/восстанавливает состояние, включая вложенность и return;
  это подтверждено машинными тестами. Чистая арифметика не получает временных гарантий.
- Volatile-метаданные происходят из общего shared-графа; разные пины допускаются
  благодаря явным атомарным операциям backend. Защита многобайтовой памяти сохранена.
- Гипотеза о допустимости обычного IR-вызова ISR отвергнута: явная проверка уже есть
  в `src/ir/verify.rs:543–547`. LLVM использует отдельную signal-wrapper функцию.
- Directed tolerance проверен существующим сравнением с полным перебором аппаратных
  вариантов. Ошибки «только плюс/минус» на точном совпадении не обнаружены.
- Unknown для стека/WCET — корректная граница результата B3, не недоделанный расчёт,
  который нужно срочно заменить приблизительным числом.

## Готовность к UART/std

| Область | Уже есть | Нужно перед первым UART | Можно отложить |
| --- | --- | --- | --- |
| Идентичности | AnalyzedProgram, SymbolId, BodyId; semantic.rs | ID аппаратного ресурса и привязка конфигурации к нему | Полные lifetimes/ownership |
| Доступ | shared.rs: память, GPIO, roots setup/main/ISR | Конфликты владения UART и его пинами; контекст каждой операции | Общая система эффектов для любых библиотек |
| Target | microcontroller.rs, emitter получает descriptor | Один descriptor через planner/verifier/toolchain/report (R02) | Внешний формат R03 и второй MCU |
| Lifecycle | lower.rs/verify.rs: initialize, setup, TimerStart, loop | UART готов до setup; IRQ запускаются явно после setup | Пользовательская динамическая перенастройка |
| ISR | Module.interrupt_handler, одиночный Timer1 | Не наращивать singleton специальным UART-полем | Таблица векторов обязательна до IRQ-driven UART, не для polling TX |
| Типы/вызовы | bool, PinState, 8/16-bit; аргументы/return | Байтовый примитив и фиксированная конфигурация | Строки, массивы, форматтер, интерполяция |
| Библиотеки | Обычные функции | Выбрать способ передачи статического доступа до публичного reusable API | Универсальные traits/generics, heap |
| Верификация | IR verifier, interpreter, AVR8js, полный gate | UART-проверки порядка/эффектов и совместимости с Timer1 | Доказанный стек и WCET |

Polling UART как узкий встроенный примитив возможен уже без модулей и ссылок. Но это
ещё не доказательство готовности std: если библиотека знает единственное глобальное
имя `debug`, ресурс не параметризован. Нужен отдельный проверяемый пример передачи
статического доступа в helper. Не обещать библиотечную независимость до его реализации.

## Timer: сравнение направлений

| Вариант | Цена и свойства | Оценка |
| --- | --- | --- |
| Оставить отдельным во всех слоях | Дешевле сейчас; UART получит ещё один lifecycle/резервирование, затем RX — ещё один ISR-путь | Допустимо только как короткий прототип; плохая постоянная основа |
| Сохранить синтаксис, привести к общему внутреннему ресурсу | Текущие программы и source diagnostics сохраняются; один lowering и общий lifecycle; Timer1 CTC остаётся проверенной аппаратной моделью | Рекомендуется |
| Сделать timer целиком библиотекой над device | Потребуются передача ресурса, библиотечные конфигурации, обработчики и compile-time расчёт периода/допуска | Отложить до реальных библиотечных механизмов |

Во втором варианте слово `device` не обязано немедленно появляться в языке.
Не нужен второй путь lowering или преобразование в текст с повторным парсингом.
Существующий TimerStart следует разделить на настройку/запуск ресурса и общий запуск
IRQ: сейчас он одновременно настраивает Timer1 и выполняет `sei`. Изменение делать
при сохранении тестов точного порядка и отсутствия ISR до завершения setup.

## Минимальные контракты для обсуждения

1. Приложение статически резервирует ресурс; import сам оборудование не захватывает.
   Проверяются повторное владение, вектор, аппаратные пины и конфигурация. UART-пин
   нельзя одновременно считать независимым обычным GPIO. TX/RX sharing пока не обещать.
2. Ссылка на ресурс не является обычным копируемым числом/указателем. Для начального
   helper достаточно статически разрешаемого параметра без хранения и переназначения;
   точный синтаксис отдельно согласовать. Это не требует общей системы Rust borrowing.
3. Для каждой операции явно заданы: доступ к ресурсу, допустимые фазы, IRQ-требование,
   блокирующая/неблокирующая семантика. Не выводить безопасность ожидания из volatile.
4. Разделить «требует IRQ off» и «для прогресса нужны IRQ on». Polling TX может быть
   допустим в noInterrupt/setup; ожидание места в IRQ-очереди там недопустимо.
   Это проектируемый контракт, UART ещё не реализован. Допуск прямого вывода из ISR
   согласовать отдельно, без молчаливого вечного запрета на всю периферию.
5. UART инициализируется до первого использования в setup; Timer1 сохраняет запуск
   после setup. IRQ включаются один раз общей фазой. Проверять также программу UART
   без timer: наличие Timer1 не должно становиться условием работы другого устройства.

Предлагаемое ядро API (названия, не готовый синтаксис): `try_write_byte(u8): bool`
возвращает false без записи, когда нет места; `write_byte(u8)` ждёт принятия байта
передатчиком; `flush()` ждёт завершения передачи. «Принят» и «полностью передан» —
разные события. Точные флаги/гонки flush проверять по документации MCU при реализации.
Форматтер и `$temperature` строятся над байтовым выводом; границы сообщений и
межбайтовые паузы не обеспечиваются самим названием write/flush или noInterrupt.

## Предлагаемый порядок и условия завершения

Порядок согласован пользователем; выполнение фиксируется в DEVELOPMENT_PLAN.

1. **Уточнить B3:** две находки выше, небольшие регрессии, отдельный коммит.
2. **Выполнить R02 раньше UART:** единожды выбрать descriptor, передать через весь
   путь; не добавлять внешний формат и второй MCU. Проверить прежние ошибки, все
   машинные тесты и совпадение контрольных артефактов при тех же настройках.
3. **Общий аппаратный lifecycle и резервирование:** перенести нынешний Timer1 в общую
   внутреннюю модель без изменения синтаксиса; сохранить SREG, GPIO, shared и tolerance.
   Таблицу ISR реализовать здесь либо отдельным этапом до RX/IRQ, не выдавать singleton
   с новым UART-полем за общую модель. Весь шаг должен проверяться без готового UART.
4. **Согласованный UART TX polling:** фиксированная конфигурация, три байтовых операции,
   конфликты GPIO/ресурсов, работа в setup/loop/noInterrupt. Проверки: байты и порядок
   в эмуляторе, отсутствие зависания без IRQ, одновременный Timer1, сохранение
   поведения в none/speed/size. Плату проверять отдельно; после согласования прошивки.
5. **Минимальный reusable helper:** передача статического доступа и небольшой вывод
   значения. По этому примеру выбирать import/форматтер, затем RX и буферы отдельными
   контрактами. Не связывать завершение TX с полной интерполяцией или всеми драйверами.

## Как сохранить обозримость

Каждый этап: один наблюдаемый контракт, отрицательные примеры, минимальный машинный
сценарий, отдельный коммит и обновлённый статус. Общая модель не считается готовой
только по наличию enum/trait; она должна заменить старый специальный путь.

Текущий host CI пропускает ignored machine-тесты по устройству workflow. Это известная
граница, не провал текущего локального gate. До автоматических релизов нужен отдельный
машинный gate с закреплённым toolchain либо сохраняемый результат локального полного
прогона, привязанный к коммиту. Зелёный host CI сам по себе не подтверждает backend.

Не требуется сейчас: дробить файлы ради числа строк, строить универсальный framework
драйверов, доказывать WCET для любого кода или реализовывать весь каталог BASIC.
Нужны общие идентичности, явные эффекты/фазы и проверяемые небольшие изменения.
