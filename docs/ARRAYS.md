# Массивы, временные слайсы и Clone

Реализовано 28 октября 2026. Это source → semantic → typed IR → LLVM AVR,
а не тестовые описания будущих типов. Пример: `examples/
uart-array.he`.

## Типы и инициализация

```helium
var global: [u8; 16] = [0; 16];

fn clear(data: &mut [u8; 16]) {
    var i: u16 = 0;
    while i < data.len() {
        data[i] = 0;
        i = i + 1;
    }
}

setup {
    var buffer: [u8; 16] = [65; 16];
    clear(&mut buffer);
}
loop {}
```

* `[T; N]`: N — целочисленный литерал 1..1024. Это ограничение текущего компилятора,
  не гарантия наличия SRAM/стека для каждого допустимого типа.
* Элементы: bool, PinState и целые. Машинный backend поддерживает i8/u8/i16/u16;
  более широкие целые сохраняют прежнюю границу typed IR / machine support.
* `[a, b, c]` вычисляет элементы слева направо; завершающая запятая допустима.
* `[value; N]` вычисляет scalar value **один раз**, затем повторяет значение.
* Требуется полная инициализация. Неинициализированные и частично инициализированные
  массивы, вложенные массивы, элементы-структуры/ссылки пока не поддерживаются.
* Тип элементов задаёт контекст декларации/аргумента/возврата. Без контекста обычные
  неконкретизированные целые становятся i32, который после N1 исполняется и на AVR.
* `.len(): u16` — фиксированная длина; `a[index]` читает, `a[index] = value` записывает.
  Получатель — именованный массив или ссылочный параметр, не временный результат.

Глобальные массивы занимают статическую SRAM; локальные — автоматическую память
вызова (LLVM alloca, обычно стек). Heap не используется. Конкретные регистры,
устранение копирований и размещение определяет LLVM. Анализ максимального стека,
совместного стека main/ISR и WCET этим этапом не добавлен.

## Владение и временный доступ

Массивы не Copy. Инициализация/присваивание/аргумент/возврат по значению передают
владение; старое значение недоступно, полное присваивание восстанавливает доступ.
Это проверяется существующим ownership-проходом через реестр способностей типа.
Глобальные владельцы не перемещаются из хранилища: их нужно заимствовать.

`&[T; N]` и `&mut [T; N]` допускаются как параметры и непосредственные аргументы
синхронного вызова. `fn helper(data: &mut [u8;16]) { clear(data); clear(data); }`
делает два последовательных временных заимствования, не перемещает исходный доступ.
Изменяющий параметр можно временно передать читающему helper.

Несколько читающих ссылок на один массив разрешены; изменяющая ссылка эксклюзивна.
Заимствования аргументов действуют до завершения вызова, включая вычисление следующих
аргументов. Проверяется весь массив, не отдельные элементы/диапазоны. Проверки включают
прямой доступ, перемещение/переприсваивание, helpers, транзитивный доступ к глобалам.
Например, `inspect(&global)` запрещён, если inspect или его helper изменяет global
через глобальное имя, даже внутри noInterrupt.

При индексированной записи массив зарезервирован от изменения/перемещения на время
вычисления индекса и RHS; RHS может читать его: `a[0] = a[1]` допустимо. При чтении
индекс не может через helper изменять заимствованный массив.

Отдельный existing shared-access анализ учитывает Borrow/IndexAssignment как доступ
к глобальному ресурсу. Изменяющее заимствование считается потенциальной записью
на всё время вызова. Общий доступ из main/ISR требует прежних IRQ-контрактов и защиты;
&mut не выключает IRQ. noInterrupt не снимает запрет конфликтующих aliases.

Пока запрещены локальные/глобальные переменные со ссылочным типом массива,
возврат ссылки, условный выбор ссылочного аргумента, изменение привязки ссылочного
параметра. Общие `&scalar` / `&mut scalar` и ссылки на элементы реализованы по REFERENCES.md.
Сохраняемые ссылки и lifetimes требуют отдельного решения. Копирование &str сохраняет прежний контракт.

## Выход за границы

Индекс приводится к u16 только разрешённым расширением; константный неверный индекс
(включая чистые +, -, * с учётом wrapping-семантики) даёт ошибку до IR/оптимизаций.
Изменяемая переменная, даже инициализированная литералом, требует runtime-проверки.

Каждое чтение/запись в IR содержит обязательную проверку `index < N`.
LLVM может удалить доказанно избыточную проверку. Для остальных на ATmega328P
ошибка отключает IRQ и останавливает выполнение бесконечным циклом. Чтение/запись
за пределами массива не происходит; автоматического reset или восстановления нет.
Состояние периферии не приводится автоматически к какому-либо безопасному состоянию.
Проверяемый доступ с результатом/запасным значением и обработчик ошибки — будущие API.
У записи индекс и RHS вычисляются до проверки непосредственно перед store.
Интерпретатор возвращает `Error::Bounds` вместо моделирования бесконечного цикла.

## Реализация и проверяемые границы

* StaticType/IR различают владеющий массив и читающую/изменяющую ссылку. Типы токенов
  теперь хранятся по значению: составные типы не требуют утечек через static lifetime.
* IR содержит создание массива, повторение scalar, адрес локального/глобального
  хранилища, reborrow, проверяемое чтение/запись. Ссылка содержит SRAM-адрес;
  длина известна из типа. В LLVM владелец — `[N x T]`, ссылка — ptr.
* Verifier проверяет размеры, элементы, mutability, инициализацию адресуемой локальной
  памяти, запрет scalar-констант для массивов/ссылок и запрет escaping-reference ABI.
  Он не заменяет source-анализ владения/заимствований.
* Доступ через array-reference пока всегда volatile, в том числе к локальным данным.
  Это консервативная реализация видимости для ISR; оптимизация provenance отдельно.
* Интерпретатор различает снимок массива-значения и стабильное адресуемое хранилище.
* Специализация &str поддерживает новые array-операции/параметры: текстовые helpers
  могут принимать массивы/ссылки без потери remapping-инвариантов.

`tests/arrays.rs` проверяет source-программы, ошибки перемещения/заимствований,
инициализацию, bounds, повторную передачу helpers, глобальные aliases, IRQ-защиту,
повреждённый IR и усечённые программы. Машинная матрица — 12 запусков: три уровня
LLVM × два режима Helium IR optimization × корректный/некорректный runtime-индекс.
Проверены UART-байты, глобальная/локальная SRAM, передача/возврат массива, bool,
PinState и 16-битные элементы, а также совместная работа со специализацией &str.
Артефакты: `build/arrays/*.ir` и каталоги toolchain рядом с HEX.
Физическая плата не прошивалась.

Полный gate окончательной версии: **213 тестов debug + 213 release**, fmt и Clippy,
включая все машинные сценарии. Лог: `build/arrays-full-gate.log`.

## Слайсы и исполняемый Clone — реализовано

```helium
fn fill(data: &mut [u8]) {
    var i: u16 = 0;
    while i < data.len() { data[i] = 65; i = i + 1; }
}
setup {
    var data: [u8; 16] = [0; 16];
    fill(&mut data);
    var copy = data.clone();
    copy[0] = 66; // data[0] остаётся 65
}
loop {}
```

`&[T]` / `&mut [T]` — временные слайсы в SRAM. Тип не содержит N; один helper
принимает массивы разной длины. LLVM-представление `{ ptr, i16 }` содержит адрес
первого элемента и длину в элементах (не байтах). Аллокации и копирования данных
при создании слайса нет. `.len()` читает длину; индекс проверяется до доступа.

`&array` / `&mut array` приводятся к ожидаемому слайсу. Ссылочные параметры
можно повторно передавать helpers, в том числе из `&mut [T;N]` в `&mut [T]`
и из изменяющего доступа в читающий. Обратного преобразования к фиксированному N
нет. Нельзя получить изменяющий слайс из читающего. Проверки loans, globals и ISR
те же, что для фиксированных ссылок. Заимствуется весь владелец.

Первый этап предоставляет только представление целого массива. Диапазоны,
пустые слайсы из исходника, хранение/возврат слайсов
и выбор между ссылками в условном выражении пока не реализованы. Непосредственный
ссылочный аргумент — заимствование именованного массива либо параметр-reborrow.

`.clone()` доступен именованному значению с зарегистрированным Clone и не принимает
аргументов. Для `[T;N]` результат — независимый владелец `[T;N]`; исходный массив
остаётся доступным. Скаляры копируют значение, читающие ссылки — представление,
а не данные. Ограничения на хранение и передачу ссылок продолжают действовать.
Эксклюзивные ссылки и hardware не клонируются. Клонирование перемещённого массива
и чтение через clone при активном конфликтующем заимствовании запрещены.

Module expansion формирует capability-call, semantic resolver выбирает реализацию
из того же замороженного `Contracts`, который использует ownership. Lowering получает
resolved implementation, а не строку имени метода. Для нынешних scalar-массивов
Structural Clone сводится к снимку агрегата: все допустимые элементы имеют Bitwise
Clone. LLVM может устранять лишние физические копирования с сохранением независимости.
Пользовательские Clone-функции и их эффекты ещё не исполняются; будущие структуры
потребуют обхода resolved реализаций полей, а не безусловной побитовой копии.

Новые source-тесты проверяют разные длины, повторные reborrow, независимость clone,
запрет aliases/escapes/move и динамические bounds. Машинная матрица слайсов/Clone:
три уровня LLVM × два режима IR × два runtime-индекса. Она включает UART с &str
специализацией, локальные/глобальные массивы, bool/PinState/i16/u16 и расширение
прочитанного u8 до u16. Артефакты: `build/slices-clone/`.
Самостоятельный пример: `examples/uart-slice.he`.

Временные ссылки на скаляры/элементы и замена *array_ref реализованы по REFERENCES.md.
Следом: структуры/результаты и String/форматирование
по DEVELOPMENT_PLAN.md. Создание UTF-8 текста из SRAM-буфера этим шагом не добавлено.

Проверка этапа слайсов/Clone: **224 теста debug + 224 release**, fmt и Clippy,
