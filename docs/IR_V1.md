# Helium IR v1 — контракт и реализация

Статус: реализованы представление, перевод поддержанного AST, verifier, интерпретатор
и три консервативных оптимизации. LLVM AVR использует этот IR, включая исходные функции.
Старый линейный IR и legacy backend удалены.

Добавлены `Function.requires_no_interrupt` и эффектные `InterruptSave`/`InterruptRestore`.
Verifier проверяет баланс защищённых областей на CFG, порядок восстановления и контекст
вызовов. Подробнее: [noInterrupt](INTERRUPTS.md).

## Место в компиляторе

```text
source -> parser -> analyzer -> typed AST -> Helium IR v1
                                              |-> verifier (по настройке)
                                              |-> оптимизации (по настройке)
                                              |-> дамп / тестовый интерпретатор
                                              `-> LLVM AVR -> ELF/HEX
```

`compile_typed_ir(source, mcu, Options)` возвращает `Module` или диагностику.
`build --emit ir` выводит типизированное представление. `compile_llvm` переводит поддержанный исходник в LLVM IR.

Успешное построение нового IR не означает поддержку программы машинным backend.
`check` по-прежнему проверяет именно возможность генерации AVR-кода.

## Сущности и идентификаторы

`Module` содержит целевой контроллер, глобальное хранение, пины, функции и точку входа.
Функции имеют сигнатуру, локальное хранение, входной блок и набор блоков.

`FunctionId`, `GlobalId`, `PinId` — разные Rust-типы. `ValueId`, `LocalId`, `BlockId`
дополнительно содержат `FunctionId` владельца. Физических регистров AVR здесь нет.
После удаления блоков идентификаторы не перенумеровываются; пробелы в нумерации допустимы.

Каждое значение имеет ровно одно определение. Параметры функции — определения значений
на входе. Использование должно следовать за определением в том же блоке либо определение
должно доминировать над блоком использования. У недостижимых блоков проверяются ссылки
и типы, но не доминирование между блоками и определённая инициализация локальных переменных.

Переменные представлены отдельным хранением и операциями чтения/записи. Место хранения
не предписывает SRAM или стек: будущий backend может убрать его или разместить в регистрах.
`phi` и параметры блоков в v1 отсутствуют. Слияние результатов ветвей использует временные
локальные переменные; далее возможна SSA-промоция, в том числе через LLVM mem2reg.

## Типы и арифметика

Типы значений: `bool`, `PinState`, знаковые и беззнаковые целые 8/16/32/64 бит.
`void` выражен отсутствием результата функции и не является типом значения.
Неопределённых типов и нетипизированных литералов в готовом IR нет.

Модель и интерпретатор поддерживают все перечисленные целые ширины. Машинный LLVM
backend сейчас поддерживает 8/16 бит; расширение остальных ширин — отдельный этап.

- Целочисленные `add`, `sub`, `mul`, знаковый `neg` оборачиваются по ширине типа.
- Знаковые числа используют дополнительный код; переполнение не является undefined behavior.
- Сравнения учитывают знаковость. Их результат — `bool`.
- `bool` и `PinState` имеют только канонические значения 0 и 1 и не смешиваются неявно.
- Литерал вне диапазона — ошибка, а не оборачивание. Без контекста целый литерал — i32.
  Отрицательный литерал проверяется целиком, поэтому `-128` допустим как i8.
- Преобразования представлены явным `widen`, сохраняющим все значения исходного типа.
  Результат операции сначала вычисляется в типе операндов, затем расширяется, если требуется.
  Например, сложение двух u8 может обернуться до расширения результата в u16.
- Деление, остаток, сдвиги, float, строки, указатели и массивы не входят в исполняемое v1.
  Их построение отклоняется диагностикой. Правила деления/сдвигов нужно согласовать отдельно.

## Управление и порядок выполнения

Каждый блок содержит список инструкций и отдельную обязательную завершающую операцию:
`jump`, `branch` с условием bool или `return`. Инструкций после неё быть не может по структуре.
Внутренний builder временно хранит незавершённые блоки и не выдаёт их как готовый Module.

Выражения вычисляются слева направо. Присваивание сначала вычисляет RHS, затем записывает
результат. `A = B = HIGH` записывает B, затем A. Чтение переменной получает снимок значения
в точке чтения, даже если следующая часть выражения изменяет эту переменную.

`and`/`or` используют короткое замыкание. Тернарное выражение выполняет только выбранную
ветвь. `if` и `while` переводятся в блоки; `for` пока отклоняется, поскольку контракт
включительности границ и поведения счётчика при переполнении ещё не принят.

## Аппаратные эффекты

`read_pin`, `write_pin`, `set_pin_mode` оперируют `PinId`. Допустимость физических пинов
проверяется по целевому контроллеру. Режимы v1: INPUT, OUTPUT, INPUT_PULLUP.
Режим — непосредственный параметр операции, не вычисляемое значение или переменная.

Чтение пина — чтение фактического входного уровня, включая пин в режиме OUTPUT. Каждое
выполненное чтение наблюдаемо, даже если результат не используется. Запись не означает,
что последующее физическое чтение обязательно вернёт записанное значение.

```text
v0: PinState = read_pin p0
v1: PinState = not v0
write_pin p0, v1
```

Так реализуется `Led = !Led`: одно чтение и одна запись, без обещания атомарности.
`!Led` отдельно ничего не записывает. Типизацию исходных pin-выражений всё ещё определяет
analyzer; например, Pin и PinState не становятся взаимозаменяемыми типами во всех контекстах.

Порядок выполненных аппаратных эффектов сохраняется. Нельзя объединять чтения или
устранять выполненную запись, даже если записывается то же значение. Эффекты из доказанно
недостижимой ветви можно удалить, поскольку исходная программа их не выполняет.

Обычный StoreGlobal не обозначает MMIO. Особые аппаратные правила (например,
write-one-to-clear для Timer1) реализуются в target lowering. Контракт прерываний
и асинхронной видимости глобальных переменных описан в [TIMERS.md](TIMERS.md).

## Функции и запуск

IR содержит типизированные вызовы, параметры и возврат значения. Пользовательский синтаксис
`fn` описан в [FUNCTIONS.md](FUNCTIONS.md). Каждый вызов консервативно считается эффектом; неиспользуемый результат
не разрешает удалить вызов. Рекурсивные циклы в графе вызовов пока запрещены.

Для исходной программы создаются `$entry`, `$setup`, `$loop`. Входная функция выполняет:

1. Инициализаторы глобальных переменных в порядке исходного кода.
2. Настройки пинов из def в порядке исходного кода.
3. Единственный вызов setup.
4. Повторные вызовы loop без завершения программы.

Стартовая среда обязана предоставить начальное нулевое глобальное хранение до входа.
Стек, ABI и загрузку данных в SRAM обслуживают LLVM AVR и стартовая среда AVR.
Ни размер стека, ни длительность операций текущий IR не обещает.

## Происхождение и диагностика

Инструкции, блоки, объявления и функции содержат `Origin`: позицию исходного кода или
явную причину генерации. Завершающая операция использует происхождение своего блока.
Оптимизации сохраняют происхождение заменённых инструкций.

Неподдержанный исходный код получает обычную диагностику `E_UNSUPPORTED` с позицией.
Поломка инвариантов компилятора получает `E_INTERNAL_IR` с этапом и деталями verifier.
Это внутренняя ошибка компилятора, а не ошибка пользователя.

## Политика verifier

| Режим | Полная проверка IR |
| --- | --- |
| Debug-сборка | По умолчанию после построения и после каждого оптимизирующего прохода |
| Release-сборка | По умолчанию включена |
| `--verify-ir` | Включена и в release |
| Библиотечный API | Явное поле Options.verify; default=true во всех профилях |

Проверки исходных типов, имён и диапазонов включены всегда. Отключение verifier не
разрешает невалидную программу. Verifier проверяет внутреннюю структуру, но не доказывает
семантическую эквивалентность: замена сложения вычитанием может быть структурно корректной.

Проверяются ID, сигнатуры, типы результатов/операндов, переходы, однократные определения,
доминирование и чтение локального хранения только после инициализации на каждом достижимом пути.
Тесты намеренно портят эти свойства и проверяют категории отказов.

LLVM — единственный машинный путь. Он всегда строит typed IR; verifier проверяет его
по Options.verify, по умолчанию true. Параллельного legacy-генератора нет.

## Интерпретатор и оптимизации

Интерпретатор предназначен для тестов, не является эмулятором AVR. Он проверяет Module
при создании независимо от профиля, имеет лимит шагов и глубины вызовов, записывает
чтения, записи и настройки пинов. Входные уровни задаются очередью; после её исчерпания
используется установленный физический уровень (по умолчанию LOW). Записи не меняют входы.

`run_entry` выполняет настоящий бесконечный жизненный цикл до лимита шагов.
`invoke` позволяет тестам вызвать конечную функцию отдельно, но не выполняет за неё
инициализацию entry. Для сравнения оптимизаций следует сравнивать полные конечные выполнения,
а не префиксы, обрезанные одинаковым числом IR-инструкций.

Оптимизации включаются только явно (`--optimize-ir` для `--emit ir`):

1. Свёртка чистых константных выражений с арифметикой Helium.
2. Упрощение константных ветвей и удаление недостижимых блоков.
3. Удаление неиспользуемых чистых значений, включая каскадное удаление.

Нет устранения записей, CSE, перемещения эффектов, предположений о чистоте вызовов
или анализа значений изменяемой памяти. Регрессионные тесты сравнивают итоговое глобальное
хранение и аппаратные трассы, в том числе на всех 512 комбинациях девяти входных чтений.
Отдельные тесты задают ожидаемые результаты арифметики, не полагаясь только на сравнение
двух запусков одного интерпретатора.

## Следующая граница

Ограниченный LLVM-прототип реализован: перевод этого IR, volatile-обращения к GPIO,
вычисления 8/16 бит, вызовы, стартовая среда и получение HEX. Машинные тесты и сравнение
с 40-байтным GPIO-примером описаны в [LLVM_PROTOTYPE.md](LLVM_PROTOTYPE.md).
Путь LLVM получает неоптимизированный Helium IR; собственные passes остаются опциональным
экспериментом для `--emit ir`. Выбор окончательного backend ещё не сделан.

## Timer lifecycle

A module optionally carries a Timer1 configuration, an ISR function ID and a set of
ISR-accessible globals. `InterruptDisable` and `TimerStart` are entry-only effects;
startup disables interrupts before initialization and starts the timer after setup.
The ISR is an externally reachable root and cannot be called as a normal function.
Its global accesses, including through helpers, are volatile in LLVM. Global loads
are conservatively retained by Helium DCE. The verifier checks visibility metadata,
configuration and lifecycle order. The interpreter does not dispatch asynchronous ISR.
# Lifecycle verification (A1)

Source modules carry explicit `Lifecycle` roles: initialize, setup and loop body.
The entry wrapper calls a separate initializer (globals in source order, then GPIO),
then setup, then the repeating loop. With Timer1 it first disables interrupts and
starts the timer only after setup. Initializers may contain arbitrary expression CFG.
The verifier checks the wrapper order, distinct role IDs, a single startup path and
no lifecycle calls from helpers or ISR. It does not assume setup has function ID 1.
Standalone IR test modules may omit lifecycle metadata; timer modules may not.
