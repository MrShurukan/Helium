# LLVM-прототип для ATmega328P

Прототип реализует полный путь от исходника Helium до прошивки:

```text
Helium → AST → Helium IR v1 → LLVM IR → opt → llc → AVR object
                                                       ↓
                                   avr-gcc + avr-libc → ELF → HEX
```

Старый backend остаётся выбранным по умолчанию (`--backend legacy`). Новый включается
через `--backend llvm`. Это экспериментальная реализация, а не смена backend всего проекта.
Первоначальные машинные проверки выполнены в AVR8js; позже пользователь подтвердил работу
базового latch на Arduino Nano. Новые исходные функции описаны в [FUNCTIONS.md](FUNCTIONS.md).

## Установка и запуск на Windows

```powershell
./tools/setup-toolchain.ps1
. ./tools/activate-toolchain.ps1
cargo build --locked --release
./target/release/helium.exe build examples/llvm-counter.he --mcu atmega328p --backend llvm --opt size -o build/counter.hex
```

Установка локальна для checkout: `build/toolchain/`, без изменения системного PATH или реестра.
Версии и SHA256 всех архивов закреплены в `tools/toolchain-lock.json`:

- LLVM **23.1.3**, пакеты MSYS2 UCRT64 с AVR target и зависимостями.
- AVR GCC **7.3.0-atmel3.6.1-arduino7**, binutils и avr-libc из Arduino toolchain.
- AVR8js **0.21.1**, только для машинных тестов. Нужен Node.js **20.19+**; он не устанавливается скриптом.

Скрипт скачивает опубликованные архивы, сверяет SHA256 и распаковывает их. Lifecycle scripts
пакета npm не запускаются. Повторный запуск использует проверенный кеш загрузок.
Если закреплённый архив исчезнет с зеркала MSYS2, обновление lock-файла должно быть явным,
с повторной проверкой backend; автоматической подмены версий нет.

`activate-toolchain.ps1` задаёт только переменные текущего PowerShell:
`HELIUM_LLVM_BIN`, `HELIUM_AVR_BIN`, `HELIUM_AVR8JS`. Первые две содержат директории бинарников,
третья — директорию распакованного пакета AVR8js. Без первых двух компилятор ищет программы
в PATH. Тесты используют `node` из PATH либо `HELIUM_NODE` с полным путём к Node.js.
Для прежних AVRA-тестов `avra` по-прежнему нужен в PATH.

При выборе другой поставки LLVM необходимо проверить `llc --version`: в списке targets
должен присутствовать AVR. Проверенная официальная Windows-сборка LLVM 21.1.8 его не содержит.
LLVM backend обнаруживает отсутствие AVR и возвращает понятную ошибку.

В ограниченной Windows-песочнице Codex 32-битный Arduino AVR GCC не запускался
(ошибка Windows 623); в обычном процессе полный набор тестов прошёл. Поэтому интеграционные
проверки в этой сессии выполнялись вне песочницы. Это не требование прав администратора.

## CLI и артефакты

```powershell
# Проверка поддерживаемого подмножества, без внешних программ:
./target/release/helium.exe check examples/llvm-counter.he --mcu atmega328p --backend llvm

# Неоптимизированный LLVM IR, без LLVM/GCC на машине:
./target/release/helium.exe build examples/llvm-counter.he --mcu atmega328p --backend llvm --emit llvm -o build/counter.ll

# LLVM assembly, ELF или HEX:
./target/release/helium.exe build examples/llvm-counter.he --mcu atmega328p --backend llvm --emit elf --opt speed -o build/counter.elf
```

`--emit asm` у LLVM выдаёт GNU/LLVM AVR assembly, которую нельзя подавать в AVRA.
`--emit llvm` всегда выдаёт исходный LLVM IR и не принимает `--opt`.
Форматы `ir`, `legacy-ir`, `ast` остаются отдельными командами инспекции без `--backend llvm`.

Каждая машинная сборка создаёт отдельную директорию `llvm-<pid>-<timestamp>` рядом с результатом.
Там сохраняются `module.ll`, `optimized.ll`, `program.s`, а для ELF/HEX также объектный файл,
ELF, карта линковки, список символов, размеры секций и дизассемблирование.
Выбранный выходной файл записывается только после успешного завершения нужных стадий.
Директория промежуточных файлов сохраняется и при ошибке, чтобы её можно было исследовать.

Режимы оптимизации:

| CLI | LLVM IR | Генератор машинного кода |
| --- | --- | --- |
| `--opt none` (по умолчанию) | `default<O0>` | `llc -O0` |
| `--opt speed` | `default<O2>` | `llc -O2` |
| `--opt size` | `default<O2>`, функции `minsize optsize` | `llc -O2` |

В LLVM 23 прежний pipeline `default<Oz>` заменён политикой размера через атрибуты функций.
У Helium выбор остаётся `size`, без привязки пользовательского интерфейса к этому изменению LLVM.
Никакие собственные оптимизации Helium перед LLVM не запускаются. `--optimize-ir` остаётся
для исследования Helium IR; сочетание с LLVM backend отклоняется.

## Контракт перевода

- Поддерживаются bool, PinState, u8/i8/u16/i16; переменные, ветви, while, короткое замыкание,
  тернарное выражение, add/sub/mul/negate, сравнения и допустимые расширения типов.
- Числа шире 16 бит пока явно отклоняются; анализ языка и IR-интерпретатор по-прежнему их знают.
- Сложение, вычитание, умножение и отрицание не получают `nsw`/`nuw`: signed overflow Helium
  остаётся циклическим, включая `-(-32768)`. Для сравнений и расширений учитывается знаковость.
- Слоты локальных переменных размещаются в отдельном входном блоке через `alloca`, поэтому
  переходы внутри исходного CFG не выделяют повторно стек. LLVM затем может заменить их SSA-значениями.
- Функции AVR находятся в program address space 1. Обычные переменные — в data space 0.
  `opt` устанавливает layout из выбранной AVR-цели; host layout не используется.
- Вызовы, параметры и возвращаемые значения поддержаны в IR и синтаксисе `fn` Helium.
  Это не обещание совместимого публичного C ABI или поддержки FFI.
- Пины B/C/D преобразуются в адреса регистров ATmega328P. Чтение физического PIN и обращения
  к DDR/PORT используют `volatile`. Неиспользованное физическое чтение сохраняется.
- `Led = !Led` делает одно чтение PIN. Запись изменяет соответствующий бит PORT с сохранением
  остальных битов; чтение PORT при такой записи не является вторым физическим чтением PIN.
- INPUT отключает выход и pull-up; INPUT_PULLUP отключает выход и включает pull-up;
  OUTPUT включает выход, сохраняя latch. Эти операции не объявлены атомарными относительно ISR.
- Стартовый код avr-libc устанавливает стек, нулевой регистр, инициализирует `.data`/`.bss`
  и вызывает `main`; обёртка вызывает entry Helium. Нет Arduino runtime и скрытого heap.

Верификатор Helium сохраняет прежнюю политику: включён по умолчанию в debug,
выключен в release, включается явно через `--verify-ir`. Emitter ожидает корректный IR;
он не дублирует полный verifier. Стандартные проверки LLVM остаются частью запуска его инструментов.

## Проверки

```powershell
. ./tools/activate-toolchain.ps1
cargo test --locked
cargo test --locked -- --include-ignored
cargo test --locked --release -- --include-ignored
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
./tools/benchmark-llvm.ps1
```

В первоначальном прогоне 2026-10-23 прошли **60 тестов** в debug и **60 в release**, включая AVRA.
Один интеграционный тест включает **30 независимых сборок HEX и запусков AVR8js** для каждого
профиля Rust: три режима LLVM × десять сценариев. При обычном `cargo test` три внешних
интеграционных теста пропускаются с явными пояснениями, а не считаются выполненными.

Машинные сценарии сравнивают глобальные значения, упорядоченные GPIO-чтения/записи и итоговые
DDR с интерпретатором. Проверены переполнения 8/16 бит, signed comparison/extension,
локальный while, ternary, физическая инверсия, короткое замыкание на четырёх входных последовательностях,
соседние биты PORT, смена режимов и чтение пина с неиспользуемым результатом.
В тесте вызова смешаны i16/i8 параметры и i16 результат; `noinline` на тестируемой функции
сохраняет реальный AVR call даже после O2. Наличие вызова проверяется по дизассемблированию.

Для наблюдения за глобальными результатами тестовый emitter может экспортировать символы.
Дополнительный GPIO-сценарий использует обычный production linkage. Конечные тесты заменяют
только бесконечное повторение loop в entry на один полный проход, сохраняя инициализацию.
Машинный тест проверяет Intel HEX checksums, ограничивает выполнение миллионом инструкций
и требует достижения avr-libc exit; таймаут не считается успехом.

## Первые измерения

Release-компилятор, закреплённая цепочка выше, один локальный запуск каждого варианта.
`tools/benchmark-llvm.ps1` сохраняет подробности в `build/llvm-benchmark/results.json`.
Числа — байты, время — весь процесс компилятора и внешние программы, без установки и сборки Rust.

| Пример | Режим | Flash всего | Код Helium + main | Runtime / padding | Статическая SRAM | Время, мс |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| GPIO baseline | none | 214 | 82 | 132 | 0 | 238 |
| GPIO baseline | speed | 164 | 32 | 132 | 0 | 219 |
| GPIO baseline | size | 164 | 32 | 132 | 0 | 213 |
| typed-ir, счётчик u8 | none | 356 | 208 | 148 | 1 | 210 |
| typed-ir, счётчик u8 | speed | 176 | 44 | 132 | 0 | 215 |
| typed-ir, счётчик u8 | size | 176 | 44 | 132 | 0 | 216 |
| счётчик u16 + i16 | none | 450 | 302 | 148 | 4 | 211 |
| счётчик u16 + i16 | speed | 214 | 82 | 132 | 0 | 218 |
| счётчик u16 + i16 | size | 212 | 80 | 132 | 0 | 222 |

Flash = `.text + .data`; статическая SRAM = `.data + .bss + .noinit`.
Код Helium — сумма размеров символов `main` и `helium_f*` после оптимизации и линковки.
Остаток `.text` включает векторы, startup, exit, библиотечные помощники и выравнивание,
поэтому он не называется точным размером одного startup-файла.

Legacy AVRA baseline по-прежнему **40 байт**. Полная LLVM-прошивка GPIO — **164 байта**,
из которых **32 байта** принадлежат программе и обёртке, а **132** — окружению.
Следовательно, сейчас LLVM не выигрывает размер готовой простейшей прошивки. При этом backend
уже выполняет арифметику, хранение и управление потоком, отсутствующие в legacy-генераторе.

Нулевая статическая SRAM после оптимизации означает перенос состояния этих примеров в регистры,
а не отсутствие расхода SRAM вообще: стек считается отдельно. В конечных сценариях эмулятор
наблюдал 2–17 байт стека без прерываний. Например, контрольный while: 17 байт / 265 тактов без
оптимизации и 2 байта / 66 тактов в speed/size (с учётом startup до exit).
Это измеренный максимум конкретного выполнения, не статическая гарантия глубины стека программы.
Тестовые экспортированные символы и конечный entry могут менять оптимизацию относительно firmware.

## Вывод для следующей итерации

Прототип подтверждает работоспособность связки нашего IR и LLVM AVR на покрытом подмножестве.
Пока сохраняем оба backend. Перед окончательным выбором нужны несколько прикладных программ,
включая программы с функциями и будущими драйверами, и расширенные проверки на настоящем ATmega328P.
Отдельный компактный startup имеет смысл исследовать позже с сохранением нужной инициализации,
таблицы векторов и будущих ISR. Удалять стандартный startup только ради красивого числа пока рано.

UART, таймеры, прерывания, OneWire/Dallas, LCD, модули и подключение C-библиотек не входят
в эту итерацию. Проверка LLVM-вызовов не завершает разработку ABI, ISR или FFI Helium.

Источники инструментов и контракта: [MSYS2 LLVM](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-llvm),
[Arduino package index](https://downloads.arduino.cc/packages/package_index.json),
[AVR8js](https://github.com/wokwi/avr8js), [LLVM Language Reference](https://llvm.org/docs/LangRef.html).
