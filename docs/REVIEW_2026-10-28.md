# Независимое ревью свежих итераций Helium

Дата: 28 октября 2026. Проверенный HEAD: `ae7dd671cb6b7cdf09c458fba2378108c1cfdc45`.
Ветка: `codex/reliable-compiler-base`; до проверки рабочее дерево было чистым.

Основной диапазон: `d7d3d10..ae7dd67` (контракты значений, ownership, arrays,
loans, slices/Clone и intermediates). Второй проход: `ff560d3..d7d3d10`
(текст и специализация); modules/extensions и shared/effects прочитаны на границах
новых конструкций. Это ограниченное ревью по разделу 0 HANDOFF, не повторный аудит
всего компилятора, target-описаний и Timer1.

**Результат исходного ревью:** три подтверждённых дефекта CLI, два с потерей исходников.
В исследованных сценариях не найден обход move/loan-проверок, нарушение независимости
Clone или выход за границы массива. Это результат ограниченного поиска контрпримеров,
не доказательство soundness. Описание reproducer и мест кода ниже относится к исходному HEAD.

## Исправления после ревью

По запросу пользователя R1–R3 исправлены в следующем коммите вместе с этим отчётом.
CLI проверяет основной выход по всем загруженным source paths; библиотечный
`build_with_options` также применяет protected_paths к destination до запуска toolchain.
Текстовые и машинные выходы проходят через общий `backend::output`: подготовка
в исключительно созданном каталоге рядом с назначением, повторная проверка, затем
rename готового файла. Существующий hard link заменяется как directory entry;
содержимое исходника не перезаписывается. При ошибке подготовки прежний выход
сохраняется, временный каталог удаляется. Symlink/необычный тип самого output
отклоняется; защита от конкурентной подмены родительских каталогов не обещана.
Имя machine artifact выбирается общей функцией: asm соответствует program.s.

Тест R1 включён в обычный набор. R2/R3 больше не являются ожидаемыми ошибками:
они оставлены ignored только из-за зависимости от внешнего toolchain, по принятой
в репозитории схеме; полный gate обязательно запускает их. Добавлен обычный тест
hard-link публикации, защиты прямого source path и очистки после ошибки подготовки.
Исторические красные результаты ниже сохраняются как evidence исходных дефектов.

После исправлений полный `tools/test-all.ps1` прошёл: **230 debug + 230 release**,
fmt и Clippy, все machine-тесты и все шесть review/regression-тестов включены.
Лог: `build/review-fixes-2026-10-28-gate.log`. Физическая плата не прошивалась.

## Подтверждённые findings

### R1 — P1: выходной файл может уничтожить импортированный исходник

Место: `src/main.rs:249–251`, `259–264`, `297–298`.

Минимальный проект:

```helium
// main.he
import app::helper;
var result:u8=0;
setup { result=app::helper::value(); }
loop {}
```

```helium
// helper.he
pub fn value():u8 { return 7; }
```

```powershell
helium build main.he --mcu atmega328p --emit llvm -o helper.he
```

Наблюдение: exit code 0; вместо текста `helper.he` записан LLVM IR. Проверка
destination сравнивает его только с entrypoint `input`. Все загруженные исходники
собираются в `protected_paths`, но этот список используется только для именованных
intermediates, а не для основного выхода. Та же неполная защита стоит перед машинной
веткой. Подтверждение выполнено на временном проекте, без изменения настоящих исходников.

Этот пропуск уже существует в зависимости `ff560d3` с modules; он не представлен
как регрессия, впервые введённая `ae7dd67`. Он относится к проверяемому контракту
сохранности исходников при новом workflow intermediates.

Исправление: перед любой записью выхода проверить все `project.sources.files`,
включая canonical aliases, а не только главный файл. В библиотечном API применить
`BuildOptions.protected_paths` и к destination. Проверка должна происходить до записи.

Regression: `review_output_must_preserve_imported_source`.

### R2 — P1: защита от hard links выполняется после разрушительной записи выхода

Место: `src/backend/llvm_toolchain.rs:368–369`, `378–387`.

Минимальный сценарий на временном проекте:

1. `main.he` содержит `setup{}loop{}`.
2. Создать `inspect/program.hex` как жёсткую ссылку на `main.he`.
3. Собрать:

```powershell
helium build main.he --mcu atmega328p --emit hex --intermediates inspect -o inspect/program.hex
```

Наблюдение: exit code 0, `main.he` содержит HEX вместо исходника. `canonicalize`
не распознаёт два разных hard-link имени как один файл. `artifact_directory`
разрешает совпадение выхода с `program.hex`. Затем `fs::copy(artifact, destination)`
перезаписывает общий файл. Позднее unlink перед публикацией intermediates действительно
защищает от hard links, но к этому моменту исходник уже уничтожен.

Подтверждено с реальным LLVM/AVR toolchain в debug и release. Отдельный простой
`--emit llvm -o <hard-link>` также воспроизводит старую слабость основной записи;
regression оставлен именно для нового пути `--intermediates`.

Исправление: безопасно публиковать основной выход до/вместе с intermediates, не писать
поверх существующего hard link. Например, подготовить отдельный файл и заменить
directory entry, сохраняя предварительные проверки protected sources. Проверки
canonical path не заменяют file identity. Не ограничиваться переносом нынешнего
`artifact_directory` выше: он уже вызывается перед сборкой и не ловит этот случай.

Regression: `review_output_must_preserve_hard_linked_source`.

### R3 — P2: собственный assembly artifact ошибочно считается конфликтом

Место: `src/backend/llvm_toolchain.rs:122`.

```powershell
helium build main.he --mcu atmega328p --emit asm --intermediates inspect -o inspect/program.s
```

Даже для `setup{}loop{}` выдаётся `Output must not overlap a named intermediate
artifact`. Исключение сравнивается с `program.{emit}`, то есть `program.asm`,
а фактический assembly artifact называется `program.s`. Аналогичные совпадения
`program.hex` и `program.elf` разрешены. Это ложный запрет, а не потеря данных.

Исправление: сопоставлять emit с реальным именем artifact (`asm -> program.s`)
в одном месте и использовать его и для проверки, и для публикации.

Regression: `review_assembly_can_target_its_own_intermediate`.

## Проверенные инварианты и оставшиеся границы

- Ownership использует замороженный Contracts; ветви объединяют возможные moves,
  return исключает путь, циклы вычисляют fixed point. Clone/len/index не потребляют
  владельца, но проверяют moved. Дополнительные probes не нашли нарушения.
- Loans сохраняются на время остальных аргументов и выполнения callee; global
  summaries распространяются транзитивно. Reservation допускает `a[0]=a[1]`, но
  отклоняет `a[0]=mutate(&mut a)`. Это принятый консервативный контракт, не R4.
- Source не разрешает сохранённые/возвращаемые ссылки и mutable upgrade. Прямой IR
  verifier проверяет типы, initialized address, mutability и запрещённые escapes;
  он не обещает повторять source borrow checker. Существующие mutation-тесты verifier
  прошли; исчерпывающего fuzzing повреждённого IR не проводилось.
- Новые operands и AddressLocal участвуют в remapping текстовых функций; смешанный
  пример с двумя текстами и агрегатным возвратом прошёл до/после специализации.
- LLVM делает bounds check до load/store, после вычисления RHS для записи;
  whole-array slices используют указатель и u16 длину в элементах. Поддиапазоны
  не проверены и не поддержаны. Interpreter использует backing array length.
- Shared/ISR обходы новых выражений и существующие тесты защиты прошли; volatile
  не является атомарностью. Физические IRQ timing, stack bounds и WCET не доказаны.
- Условные/вычисляемые reference arguments, grouped reborrow и `helper(ref.clone())`
  остаются ограничениями прямого named-place resolver. Никакого нового разрешения
  хранить ссылки или поддерживать user Clone-functions из этого ревью не следует.
- Успешные/ошибочные публикации и очистка временных каталогов покрыты штатными CLI
  тестами. Отдельные reparse-point/junction сценарии, конкурентная подмена путей и
  fault injection частичной публикации не проверены. Транзакционность каталога
  intermediates и concurrent builds по-прежнему не обещаны.

Архитектурно разделение Contracts / ownership / loans / shared / typed IR выглядит
последовательным для текущих scalar whole-array views. Следующее расширение на
ссылки на элементы потребует явного представления мест/происхождения aliases:
нынешняя модель по SymbolId всего массива не доказывает непересечение частей.
Structural Clone нельзя механически расширить с scalar arrays на структуры с
пользовательскими Clone-эффектами. Это границы следующего дизайна, не новые findings.
