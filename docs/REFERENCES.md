# Временные ссылки на значения — 28 октября 2026

Реализованы временные `&T` / `&mut T` для целых, bool, PinState и фиксированных
scalar-массивов, а также ссылки на элементы массивов/слайсов. Ссылки используются
как параметры и непосредственные аргументы синхронных вызовов; не сохраняются
в переменных/полях/глобалах и не возвращаются. Правила &str остаются отдельными.
После N1 в AVR доступны целые 8/16/32/64 бит, в том числе через ссылки; float-ссылки ещё не исполняются. См. NUMERIC.md.

```helium
fn increment(value: &mut u16) {
    *value = *value + 1;
}
fn twice(value: &mut u16) {
    increment(value);
    increment(&mut *value);
}
setup {
    var count: u16 = 0;
    twice(&mut count);
    var counters: [u16; 3] = [0; 3];
    increment(&mut counters[1]);
}
loop {}
```

## Значения и синтаксис

- `&x` / `&mut x` заимствуют адресуемое хранилище. Литералы и результаты функций
  не являются местами для заимствования. Скобки вокруг места допустимы.
- `*r` обозначает объект по ссылке. Чтение Copy-значения копирует его; перенос
  владельца через ссылку запрещён: `var a = *array_ref` не разрешён для массива.
  Решение Copy/Move берётся из замороженного реестра Contracts, как для имён.
- `*r = value` меняет объект через изменяющую ссылку. Для `&mut [u8;4]` разрешено
  `*r = [0;4]`. Присваивание владельца в ссылочное назначение нельзя использовать
  как значение с последующим move. Скалярное присваивание может возвращать Copy-результат.
- `r = other` не перепривязывает ссылочный параметр: запрещено.
- `data[i]` продолжает работать через array/slice reference без явной звёздочки.
  Целиком разыменовать/заменить слайс нельзя: у него нет фиксированного размера.
- `r.clone()` для читающей ссылки копирует view. `(*r).clone()` явно клонирует
  объект; для scalar-массива возвращается независимый владелец. `&mut` не Clone,
  но допускает чтение своего объекта для `(*r).clone()` при отсутствии конфликтов.
  Computed method receivers в целом не введены: Clone принимает именованное место,
  его группировку, разыменование или сгруппированный доступ к элементу.

## Повторные заимствования и границы

Будущее изменение, запрошенное пользователем: `r.clone()` станет эквивалентом
`(*r).clone()` для клонирования референта. Описание выше фиксирует текущую реализацию;
авторазыменование Clone ещё не реализовано. См. ROADMAP.md.

Передача ссылочного параметра в helper делает временный reborrow, а не забирает
доступ навсегда. После возврата параметр снова доступен. `&mut T` можно передать
в `&T`, но shared нельзя повысить до mutable, включая обход через скобки/элемент.
Явные `&*r` / `&mut *r` поддержаны; прежние `&r` / `&mut r` также означают reborrow
референта, а не создание ссылки на ссылку. Типы `&&T` и `&mut &T` не поддержаны.

Ссылочный аргумент — непосредственный Borrow места либо имя параметра.
Условный выбор ссылки, `helper(r.clone())` и обёртка всего ссылочного аргумента
в grouping пока не расширены. `helper(&(x))` допустим, `helper((&x))` — нет.
Это ограничение resolver, не утверждение об опасности лишних скобок.

Заимствование сохраняется до конца вызова, включая вычисление последующих аргументов.
Читающих заимствований может быть несколько; изменяющее исключает конфликтующий доступ.
Ограничение распространяется на прямые обращения, helpers и транзитивные global accesses.

## Элементы и порядок эффектов

`&mut a[index()]` вычисляет индекс ровно один раз. Bounds проверяются при создании
адреса элемента, **до** входа в вызываемую функцию и **до** следующих аргументов.
На AVR неверный индекс отключает IRQ и останавливает выполнение; interpreter возвращает
Bounds. Значение по адресу вне диапазона не читается и не записывается.

Во время вычисления индекса массив зарезервирован от изменения/перемещения. Проверка
loans ведётся по корневому хранилищу: заимствование элемента блокирует конфликтующий
доступ ко всему массиву, включая другие элементы. Две последовательные операции
разрешены; `swap(&mut a[0], &mut a[1])` пока отклоняется. Анализ непересечения — позже.

У `*r = rhs` адрес назначения вычисляется перед RHS, назначение зарезервировано
от конфликтующей записи, но RHS может его читать: `*r = *r + 1` разрешено.
Если адрес получается как `&mut a[index]`, bounds проверяется при его создании,
до RHS. Это отличается от существующего `a[index] = rhs`: там bounds стоит перед
store после RHS. Различие следует из явного создания ссылки и покрыто тестами.

## Main/ISR

Borrow скаляра или элемента учитывается как доступ к исходному глобальному ресурсу:
shared — чтение, mutable — потенциальная запись. Вычисления индекса также входят
в граф вызовов/эффектов. Конфликт main/ISR, где хотя бы одна сторона пишет,
требует существующей noInterrupt-защиты. Setup-only исключение сохранено.
`&mut` не отключает IRQ, а noInterrupt не разрешает конфликтующие aliases.

## Реализация и проверка

AST содержит Deref/DerefAssignment и root-place resolution. Loans используют корень
места, резервируя его во время адресных вычислений. Реестр регистрирует контракт
референта до freezing; Move/Clone не выбираются backend по имени метода.

Typed IR содержит Ref, ReadRef/WriteRef и проверяемый ElementAddress. AddressLocal/
AddressGlobal и Reborrow работают со скалярами и массивами. Verifier проверяет
типы, mutability, инициализацию локального хранилища и запрет escapes/подделки
reference через scalar constants/conversions. Он не заменяет source borrow checker.

LLVM использует SRAM ptr без heap; обращения через ссылки консервативно volatile.
Interpreter хранит стабильные ячейки локальных скаляров, адреса глобалов и элементов;
агрегатные чтения сохраняют независимость снимков. Text specialization remaps все
новые operands. Source &str не превращается в общий SRAM-буфер этим этапом.

`tests/references.rs`: положительные/отрицательные source-примеры, порядок эффектов,
global/ISR conflicts, повреждённый IR и усечённые программы. Машинная матрица —
12 запусков: LLVM none/speed/size × IR optimize off/on × корректный/OOB индекс.
Проверены UART-байты, локальные/глобальные значения, u16/i16/bool/PinState, aggregate
replacement/Clone, text specialization и отсутствие эффектов следующего аргумента
при неверном индексе. Пример: `examples/uart-references.he`; артефакты: `build/references/`.
Физическая плата не прошивалась; stack bounds/WCET и общий lifetime-анализ не доказаны.

Финальный полный gate: **238 debug + 238 release**, fmt, Clippy, все ignored
machine-сценарии включены. Лог: `build/references-full-gate-final.log`.

Далее — согласование структур и явных результатов/ошибок. Stored references,
вложенные ссылки, поля-ссылки, raw pointers и разбиение массива на непересекающиеся
заимствования остаются отдельными задачами.
