# Timer1 и ISR

На ATmega328P реализован один периодический Timer1 в режиме CTC. Пример целиком:
[`examples/timer-seconds.he`](../examples/timer-seconds.he).

```text
var seconds:u16=0;

timer clock = Timer1 {
    every: 1s,
    tolerance: 1ms,
    interrupt {
        seconds=seconds+1;
    }
}

noInterrupt fn snapshot():u16 {
    return seconds;
}

loop {
    noInterrupt {
        var now=snapshot();
    }
}
```

Объявление находится на верхнем уровне. `every` и `interrupt` обязательны;
`tolerance` необязателен и по умолчанию равен нулю. Поля можно переставлять,
но нельзя повторять. После настройки нужна запятая, после обработчика — нет.
Длительности — целые числа с единицами `ns`, `us`, `ms`, `s`.
Имя таймера резервируется, но пока не является передаваемым значением.
Повторное резервирование Timer1 отвергается. Другие таймеры пока не поддерживаются.

## Период и частота

```powershell
cargo run --locked -- check examples/timer-seconds.he --mcu atmega328p --cpu-hz 16000000
cargo run --locked -- build examples/timer-seconds.he --mcu atmega328p --cpu-hz 16000000 --opt size -o build/timer-seconds.hex
cargo run --locked -- timer-options --mcu atmega328p --cpu-hz 16000000 --timer Timer1 --every 1s
```

Частота обязательна для программ с таймером. Она описывает фактическую частоту CPU,
а не программирует генератор, fuse-биты или делитель системной частоты.
Поддерживаемый диапазон параметра: 1–20 000 000 Гц; электрические ограничения платы
компилятор не проверяет.

Период равен `prescaler * (OCR1A + 1) / cpu_hz`. Калькулятор перебирает делители
1, 8, 64, 256, 1024 и ближайшие допустимые значения счётчика 1–65536.
Выбирается минимальная абсолютная ошибка, при равенстве — меньший делитель.
Проверка допуска целочисленная. При невозможности уложиться в допуск `E_TIMER`
показывает ближайшие варианты снизу и сверху, когда они существуют, и минимальный
допуск в целых наносекундах. `timer-options` показывает варианты без внешних инструментов.
При 16 МГц 1 секунда представима точно: делитель 256, OCR1A=62499.

Допуск описывает ошибку номинального периода таймера, не точность кварца и не задержку
входа в ISR. Фаза общего аппаратного предделителя может влиять на самый первый тик.

## Запуск и безопасность

Сначала прерывания запрещаются, затем выполняются глобальная и GPIO-инициализация
и setup. После setup настраивается Timer1, очищаются ожидающие флаги, разрешаются
его compare-A прерывание и глобальные прерывания. Обработчик экспортируется как
`__vector_11` с LLVM `avr_signalcc`: сохранение регистров и RETI генерирует LLVM.
Вложенные ISR не включаются. Прямой вызов обработчика и return из его тела запрещены;
вызванные им обычные функции могут возвращать значения.

Если основная программа и ISR используют одну глобальную переменную и хотя бы одна
сторона пишет её, обращения требуют `noInterrupt`. Тело ISR и setup уже защищены;
вспомогательной функции нужен собственный блок или модификатор `noInterrupt fn`.
Проверка проходит по графу вызовов отдельно от loop и ISR. Setup-only и невызываемые
функции не создают конфликтов времени исполнения; типы и контракты вызовов в них
всё равно проверяются. Обычный helper не наследует защиту caller.
`E_SHARED_ACCESS` показывает конкретное обращение, связанное использование из ISR
и цепочки вызовов. Для GPIO конфликт определяется по конкретному пину:
соседние пины порта независимы благодаря гарантированным SBI/CBI. Запись или настройка
общего пина требует защиты; составные операции не становятся атомарными автоматически.
Контракт и машинные/физические проверки — [ATOMIC_GPIO.md](ATOMIC_GPIO.md).

Глобальные переменные, доступные из ISR, читаются и записываются как volatile.
Это сохраняет видимость, но само по себе не делает многобайтовые операции атомарными.
IR verifier проверяет конфигурацию, запуск, контракт ISR и метаданные видимости.

Длительный `noInterrupt` не останавливает таймер. Несколько событий могут слиться
в один ожидающий флаг: счётчик вызовов ISR не гарантирует измерение реального времени.
Компилятор пока не доказывает максимальную длительность ISR/критических секций и расход
стека. PWM, перенастройка, UART, другие источники IRQ и вложенные ISR — будущие этапы.

## Проверки

`tests/timers.rs` покрывает расчёты, диагностики, обрезанные программы, конфликты
ресурсов, граф вызовов, IR и CLI. Машинные тесты исполняют прошивку в AVR8js,
включая разные оптимизации и защищённые снимки 16-битного счётчика.
Интерпретатор Helium IR моделирует состояние разрешения прерываний, но не ход
времени и асинхронное исполнение ISR. Машинные тесты плату не прошивают.

```powershell
. ./tools/activate-toolchain.ps1
cargo test --locked --test timers -- --include-ignored
```
