# GPIO и атомарность — B2a

## Контракт

Операции GPIO сохраняют соседние пины того же порта. Анализ по-прежнему хранит
ресурс порта, но проверяет конфликтующую пару обращений по конкретному биту.
Это гарантия языка/backend, а не предположение о том, что LLVM выберет удобную инструкцию.

| Операция | Реализация ATmega328P | Правило main/ISR |
| --- | --- | --- |
| Чтение пина | Volatile-чтение PIN, выделение бита | Два чтения безопасны; запись/настройка того же пина требует защиты |
| Запись уровня | Явные SBI/CBI в inline asm; меняется один бит PORT | Разные пины независимы; общий пин с записью требует noInterrupt |
| Смена режима | SBI/CBI для DDR, затем при необходимости PORT | Разные пины независимы; переход режима общего пина требует защиты |
| GPIO read-modify-write целого регистра | Не генерируется для поддержанных операций | Недопустимая замена атомарной реализации, в том числе при O0 |
| Общая память, включая u8 | Обычные/volatile load/store | При записи одной из сторон сохраняется noInterrupt: чтение/вычисление/запись не являются одной транзакцией |
| Общая многобайтовая память | Несколько AVR-обращений | Защита нужна от разрыва между байтами; volatile её не заменяет |

`A = !A` сначала читает физический вход, затем отдельно записывает инвертированный
уровень. Это не атомарный toggle. Смена режима также не является одной атомарной
операцией: возможны промежуточные электрические состояния этого пина. Блок защиты
нужен вокруг всей составной операции или снимка, если ресурс разделяется с ISR.

Даже простая запись в общий пин остаётся под правилом явного noInterrupt: атомарность
одного изменения не определяет порядок конкурирующей логики приложения. Helper не
наследует защиту caller автоматически; контракт B1 сохранён.

## Генерация AVR-кода

Для постоянного состояния режима используются прямые SBI/CBI. Для вычисленного
уровня формируется i8 со значением 0 или 1 и одна sideeffect asm-последовательность:

```asm
sbrc value, 0
sbi PORT_IO, BIT
sbrs value, 0
cbi PORT_IO, BIT
```

Выполняется ровно одна запись. ISR может вклиниться между инструкциями; сохранение
регистров ISR и изменение только одного бита сохраняют независимость соседних пинов.
Memory clobber удерживает порядок эффектов; инструкции не изменяют SREG. Код не
вставляет CLI/SEI вокруг независимой записи. Все текущие DDR/PORT доступны SBI/CBI.
Для адреса без такой реализации emitter выдаёт ошибку, а не переключается на RMW.

Ограничение диапазона SBI/CBI и различие I/O/data-space описаны в
[документации Microchip](https://onlinedocs.microchip.com/oxy/GUID-0EC909F9-8FB7-46B2-BF4B-05290662B5C3-en-US-12.1.1/GUID-710586A5-D298-4BA8-8F8F-C3385CBABAB9.html).
Будущий target обязан реализовать этот же контракт либо явно отвергать операцию.
Расширенные регистры, другие модели периферии и UART не стали поддержанными автоматически.

## Проверки — 27 октября 2026

Полный `tools/test-all.ps1`: fmt, Clippy, **130 тестов в debug и 130 в release**,
включая машинные тесты. `tests/atomic_gpio.rs` проверяет:

- точные пары конфликтов (в том числе read/read при посторонней записи другого пина),
  настройки, helper-контракты, u8 RMW и многобайтовые снимки;
- наличие SBI/CBI и отсутствие прямых OUT/STS к DDR/PORT в контрольных прошивках;
- порты B/C/D, IR optimization off/on, LLVM none/speed/size: 18 комбинаций;
- искусственное планирование ISR после каждой инструкции main, сохранность чужих
  битов при каждой записи DDR/PORT, реальное продвижение обеих сторон;
- отрицательный контроль: подставленная неатомарная IN/OUT-пара теряет обновление,
  и тот же симулятор обнаруживает это. Режим инъекции не является измерением времени таймера.

### Физическая Nano

С разрешения пользователя: COM5, legacy bootloader 57600 baud, 16 MHz, свободные
D12/PB4 и D13/PB5. `tools/board-gpio/program.he` переключает разные пины из main и
Timer1 ISR (100 us), сравнивает физический PIN с ожидаемым состоянием и считает ошибки.
UART-телеметрия 9600 baud добавлена отдельным **тестовым C-модулем**, не языковым API.
Снимок счётчиков защищён кратким CLI/восстановлением SREG; передача выполняется с IRQ.

| IR optimization | LLVM | Интервал наблюдения, с | Тики ISR | Итерации main | Ошибки |
| --- | --- | ---: | ---: | ---: | ---: |
| off | none | 2.022 | 20270 | 143360 | 0 |
| off | speed | 2.015 | 20165 | 200704 | 0 |
| off | size | 2.007 | 20086 | 184320 | 0 |
| on | none | 2.026 | 20270 | 143360 | 0 |
| on | speed | 2.015 | 20165 | 200704 | 0 |
| on | size | 2.007 | 20086 | 184320 | 0 |

Интервалы измерены на хосте по UART; это smoke test, а не осциллографическая оценка
джиттера, абсолютной частоты или гарантия длительной безотказной работы. Переключение
режимов проверено в симуляторе; на плате проверялись уровни выходов PB4/PB5.
Другие порты физически не подключались к измерительному оборудованию.

Перед тестом считана исходная flash. После теста восстановлены затронутые страницы;
повторное чтение подтвердило побайтное совпадение всех 32768 байт с резервной копией.
Локальные результаты: `build/board-gpio/results.json`, CSV, upload/restore logs,
`build/b2a-full.log`. Процедура воспроизведения — `tools/board-gpio/README.md`.
