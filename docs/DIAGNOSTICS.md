# Диагностика: контракт и аудит

Итерация 2026-10-26: единственный backend — LLVM; старый линейный IR, ручной AVR-генератор,
AVRA-обвязка и неиспользуемые assembly includes удалены. Опций `--backend` и `legacy-ir` нет.
Интерпретатор Helium IR, verifier и оптимизации сохранены. Ширина машинных целых не расширялась.

## Структура и исходные координаты

`DiagnosticKind` хранит вид ошибки и её параметры; `DiagnosticCode` — enum со стабильными
строковыми кодами. `Diagnostic.location` задаёт основную позицию. `labels` содержит связанные
диапазоны и `LabelKind`: ожидаемый тип, первое объявление, тип операнда, проблемный путь,
открывающая скобка, вызов в цикле рекурсии. Пояснения и рекомендации формируются в слое
представления (`diagnostic/messages.rs`), а не извлекаются из готового консольного текста.

AST сохраняет отдельные позиции имён, аннотаций параметров/результата/переменных, операторов,
физических пинов и режимов. `SourceLocation` пока использует строки с единицы и столбцы в
графемах с нуля; диапазоны полуоткрытые. Это внутренние координаты lexer, не координаты LSP.

`SourceFile { id: FileId, name, text }` проверяет и переводит их в `SourceSpan { file, bytes }`.
`Diagnostic::source_spans` связывает основную и дополнительные позиции одной компиляции с
файлом. Некорректный диапазон возвращает None вместо незаметного смещения. CRLF, отдельный
завершающий CR, составные Unicode-символы и пустая строка в EOF проверены тестами.

CLI использует `render_in`, показывает файл/строку/столбец, цвет и связанные фрагменты.
Табуляция разворачивается по четырём экранным колонкам; Unicode-ширина считается отдельно
от исходных координат. Длинные многострочные диапазоны сокращаются посередине.

LSP ещё не реализован. Будущий адаптер преобразует байтовые позиции в согласованную с
редактором кодировку. Компиляция пока однофайловая: импорт модулей, несколько файлов внутри
одной диагностики и хранение версий документов должны быть добавлены вместе с модулями/LSP.
Автоматических исправлений нет: компилятор не вставляет произвольный return и не переносит
инициализацию в setup. Русская локализация также остаётся отдельной работой; parser/scanner
пока сохраняют некоторые английские подробности непосредственно в своих вариантах ошибок.

## Результаты аудита всех семейств

| Семейство | Проверка и итог |
| --- | --- |
| E_RETURN | Вместо диапазона всей функции сохраняются пути достижения конца. Подсвечиваются условие без else, конец незавершающейся ветки либо конец тела; тип результата отмечается отдельно. Общий последующий return снимает ошибки предыдущих ветвей. Пустой return показывает ожидаемый тип, лишний результат — само выражение и объявление процедуры. |
| E_CALL | Число аргументов показывает вызов и объявление функции. Невызываемое имя — само имя и его объявление. Использование процедуры как значения отсылает к объявлению. Запрет вызова в глобальном инициализаторе сохраняется, с явной рекомендацией setup без автоматического переноса. |
| E_RECURSION | Сохраняется цепочка имён, добавлены связанные места вызовов цикла. Проверяются и неиспользуемые функции/недостижимые вызовы. |
| E_DUPLICATE | Обе позиции имён; таблица символов сохраняет первое объявление. Применяется к переменным, функциям, параметрам, пинам и счётчикам for. |
| E_UNDEFINED | Диапазон неизвестного имени; при присваивании и вызове не выделяется всё выражение. Неизвестный тип подавляет вторичные ошибки операторов, тернарных ветвей и границ for. |
| E_INITIALIZER | Имя объявления, требующего типа/инициализатора. |
| E_FOR_TYPE | Некорректная граница диапазона вместо всего цикла. |
| E_CONDITION | Только условие; сообщение включает фактический тип. |
| E_UNARY_TYPE / E_BINARY_TYPE | Основная позиция оператора, связанные позиции операндов с их типами. |
| E_TERNARY_TYPE / E_NUMERIC_TYPE | Несовместимые ветви/операнды и их типы. Не создаётся дополнительная ошибка из уже неизвестного значения. |
| E_LITERAL_RANGE | Точный литерал, требуемый диапазон; при контекстном преобразовании добавлено место ожидаемого типа. Проверки минимальных signed и максимальных unsigned сохранены. |
| E_TYPE | Преобразуемое выражение и источник ожидаемого типа для инициализации, присваивания, аргументов и возврата. Небезопасное сужение не предлагается как автоматическое исправление. |
| E_TARGET | Ошибка параметра цели, без выдуманной позиции в исходнике. |
| E_PIN | Именно PortX.N, а не всё def. |
| E_PIN_DUPLICATE | Повторный физический пин и исходная привязка. |
| E_PIN_MODE | Режим INPUT_PULLDOWN и пояснение об отсутствии внутреннего pull-down. |
| E_UNSUPPORTED | Старые legacy-ограничения удалены. Машинная ширина типа проверяется в AST с позицией аннотации/объявления, до запуска LLVM. Типы сигнатур выделяются отдельно. Деление указывает на оператор, for — на границы. Ограничения проверяются также в недостижимом коде. |
| E_PARSE: scanner | Диапазон ошибочной лексемы вместо последнего символа; EOF — нулевой диапазон. Проверены комментарии, строки, числа, Unicode и обрезанные префиксы. |
| E_PARSE: parser | Незакрытый блок указывает на EOF и открывающую скобку. Повторные setup/loop ссылаются на первое объявление. Остальные ошибки сохраняют токен/операнд/открывающую скобку и контекст ожидания; улучшено сообщение о тернарном выражении и конце исходника. |
| E_INTERNAL_IR | Ошибки verifier, невозможные состояния после анализа и сбой продвижения parser отделены от неподдержанной пользовательской конструкции. Ошибка эмиттера после успешной проверки исходника считается внутренней. |
| CLI / внешние инструменты | Проверки аргументов, чтения/записи и ошибок запуска остаются вне исходных диагностик. Сохраняются имя инструмента, его вывод и код завершения. Исходная позиция не придумывается. Тесты проверяют отсутствие инструментов, другой рабочий каталог, неизвестные опции и сохранность существующего результата. |

## Анализ возвратов

Анализ структурный, без доказательства значений условий. Цикл может не выполниться;
`while true` пока не заменяет явный возврат в функции с результатом. Это прежняя граница
семантики, а не новое ограничение. Сохраняются конечные свидетели проблемных путей, без
перечисления всех комбинаций ветвлений. Если после условного оператора есть return,
предыдущие ветки больше не являются причиной ошибки.

Тесты `diagnostic_ranges.rs` проверяют выделенный текст, связанные места, отсутствие
каскадов, корректность байтовых диапазонов всех ошибок для обрезанных программ, а также
границу между неподдержанным исходником и внутренней ошибкой. `diagnostics.rs` сохраняет
снимки консольного вывода и проверяет одинаковое содержимое цветного/обычного рендера.
Полный прогон дополнительно выполняет LLVM/AVR-сценарии из tests/llvm.rs.

Проверка итерации: 84 теста, включая внешние LLVM/AVR-проверки; debug и release.
Машинные тесты выполняют 45 сценариев сборки/симуляции на профиль. `cargo fmt --check`
и Clippy с `-D warnings` проходят. Latch собран новым CLI без выбора backend: 184 байта
секции .text, .data — 0. Плата в этой итерации не прошивалась.
