# B3: память и видимость времени

Реализовано 27 октября 2026. Это отчёт итогового размещения и исследование ограничений,
не доказательство отсутствия переполнения стека или соблюдения real-time сроков.

## Отчёт памяти

При build --emit elf/hex отчёт читается непосредственно из связанного ELF32 AVR.
Внешний avr-size -A по-прежнему сохраняется как sections.txt для независимой проверки.
Структурированный MemoryReport доступен в llvm_toolchain::Build.memory; для asm — None.

- Flash occupied: максимальный конец файлового PT_LOAD в Flash, включая промежутки
  и образ инициализации .data. Debug-секции не входят в счётчик.
- Static SRAM reserved: от начала SRAM target до конца самой высокой SHF_ALLOC-секции
  в SRAM. Учитывает .data, .bss, .noinit, размещения с другими именами и промежутки.
- SRAM remaining for stack: ёмкость минус статическое резервирование. Не «свободная
  память» и не гарантия достаточности стека; heap сейчас не поддерживается.
- Maximum stack: unknown. Ни сумма локальных переменных, ни отсутствие рекурсии
  не дают доказанной границы машинного стека.

Ёмкости ATmega328P: Flash 32768, SRAM 2048 байт с data-space адреса 0x100;
сверены с RAMSTART/RAMEND/FLASHEND установленного avr/iom328p.h. Данные находятся
в едином описании target. Это весь MCU: место bootloader этим отчётом не резервируется.
Поддержка профилей платы/bootloader отдельно занесена в roadmap.

ELF должен быть linked little-endian ELF32 AVR. Повреждённые таблицы, неподдерживаемые
адреса и превышение ёмкости приводят к ошибке до публикации выходного файла.
Инициализация SRAM учитывается по Flash load address, а NOBITS — только по SRAM.
EEPROM/fuses/другие специальные AVR-области 0x810000..0x85ffff не являются Flash/SRAM
и в эти два показателя не входят; их ёмкости этим отчётом не проверяются.
Необычный загружаемый сегмент с load address в SRAM отвергается, а не теряется молча.
Линкер может обнаружить переполнение раньше и выдать собственную диагностику.

Отчёт сохраняется как memory.txt рядом с ELF/map/disassembly. Для asm окончательного
размещения нет: CLI предлагает сборку ELF/HEX. check не запускает линкер и не знает
итогового расхода памяти. В текстовый LLVM добавлены только комментарии инвентаризации;
кодогенерация инструкций этим этапом не меняется.

## Исследование стека

Проверены установленные LLVM AVR и AVR GNU, примеры timer-seconds и functions-latch
в none/speed/size. llc поддерживает --stack-size-section и --stack-usage-file;
получены .stack_sizes и .su, сопоставлены с disassembly объекта.

| timer-seconds | .su для __vector_11 | Инструкции push в ISR |
| --- | --- | --- |
| none | 12 bytes | 15 |
| speed | 2 bytes | 4 |
| size | 2 bytes | 4 |

Уже эта разница доказывает, что число .su нельзя использовать как полную границу.
Счётчик push также не является такой границей: требуются CFG-анализ изменений SP,
машинные вызовы/возвраты, стартовый runtime, адреса возврата, вызываемые helpers,
интервалы включённых IRQ и совмещение main с ISR. Оптимизация меняет состав функций:
в functions-latch speed/size остаётся main с .su=0, тогда как none содержит helpers
с собственными кадрами. Универсальная поправка к .su не обоснована.

Воспроизведение: собрать пример в требуемом режиме и взять optimized.ll из указанного
каталога intermediates. Запустить llc с теми же triple/cpu/-O0 или -O2, добавив
--stack-size-section --stack-usage-file=<path.su> -filetype=obj; сравнить с avr-objdump -d.
Экспериментальные файлы находятся в build/b3/stack-probe и не коммитятся.
Продакшен-сборка не зависит от экспериментальных stack flags и не публикует их числа.
Результат B3 — явное unknown и долг D09, а не скрытая приблизительная оценка.

## Видимость прерываний

В module.ll и timing.txt сохраняется инвентаризация из Helium IR до LLVM:
места IRQ masking с исходными строками/колонками, сгенерированные startup/setup,
ISR и функции с требованием noInterrupt. Для каждой такой функции указан транзитивный
список возможных вызываемых функций. Он относится ко всей функции, включая вызовы
за пределами критической секции, и так подписан. Это консервативный перечень;
неиспользуемый/недостижимый код также включён. Колонки используют принятую в Helium
модель SourceLocation. Список не является профилем исполнения или WCET.

Номинальный период Timer1, длительность ISR и задержка из-за запрета IRQ — разные
величины. Таймерный отчёт описывает первый; последние два пока unknown. Существующие
тесты задержки/слияния событий таймера продолжают проходить. Полные временные гарантии
и точная привязка транзитивных вызовов к отдельной критической секции — будущая работа.

## Проверки

Полный test-all gate прошёл с 138 тестами в каждом профиле; затем добавленный машинный
тест .data/.bss/.noinit прошёл отдельно в debug/release (всего 139), повторно прошёл Clippy.
fmt и diff --check чистые. Существующие машинные сравнительные тесты теперь сверяют
MemoryReport с avr-size и сохранённым memory.txt при разных режимах оптимизации.
Отдельно проверены разрывы размещения, превышения Flash/SRAM, обрезанный ELF и unknown.
Инвентаризация проверяется на helper и noInterrupt с исходной позицией.

Контроль timer-seconds, 16 MHz, size: 338 bytes Flash, 4 bytes static SRAM,
2044 bytes remaining for stack, maximum stack unknown. Плата в B3 не прошивалась.
