# Расширения, модули и первые функции std

Статус: именованные расширения с явным импортом и реестр методов по виду получателя
приняты пользователем и реализованы. grammar.txt синхронизирован. Будущие обёртки,
строки, массивы и общий writer-интерфейс ниже явно отделены от текущей реализации.
Имя документа сохранено для существующих ссылок.

## Принято для будущих обёрток

По решению пользователя wrapper-структура, принимающая hardware, получает
исключительное владение. Исходное имя больше не позволяет использовать или повторно
передать ресурс; обёртку-владельца нельзя копировать. Это намеренное начальное
ограничение, а не обязательство реализовать полный borrow checker. Обычный вызов
метода или helper со статическим параметром устройства владение не передаёт.

Исключительность не отключает shared-access/IRQ-проверки и не даёт доступа к любым
регистрам в обход аппаратного API. Состояние обёртки также требует защиты main/ISR.
Способ конструирования, перемещения и возможного освобождения ресурса ещё не выбран.
Реализация обёрток отложена (ROADMAP F15).

## Реализовано: именованные расширения с явным импортом

Файл lib/std/uart.he в репозитории компилятора:

```text
pub extension UartText for UartTx {
    pub fn newline() {
        self.write_byte(10);
    }
}
```

Приложение:

```text
import extension std::uart::UartText;

device debug = UART0 { baud: 38400, mode: TX, }

setup { debug.newline(); }
loop {}
```

- self — статический получатель, без runtime-указателя и передачи владения.
  Расширение не имеет собственного скрытого хранилища состояния.
- UartTx на первом этапе — встроенный вид устройства, не готовая общая система traits.
- pub делает объявление доступным из других модулей; без pub оно приватно.
  Импорт расширения открывает только его публичные методы.
- Импорт действует в текущем файле, не транзитивно. Зависимости std не открывают
  свои расширения пользователю. Импорт ничего не инициализирует и не резервирует.
- Совпадающие методы активных расширений дают ошибку при обращении; порядок импортов
  не выбирает победителя. Явный вызов: UartText::newline(debug).
  Переопределение встроенных методов устройства запрещено.
- Обычный helper получает ресурс явно: fn send_lf(device output: UartTx).
  Внутри расширения ему можно передать self. Это статическая привязка на время вызова,
  без хранения, возврата или создания второго владельца.
- Эффекты и идентичность устройства сохраняются через вызовы; import не скрывает
  blocking warnings и конфликты ресурсов. std не имеет привилегий перед пользовательским кодом.

## Размещение и сборка

std хранится исходниками Helium в lib/std/ и включается в исполняемый файл компилятора
при его сборке. Так cargo install/перенос готового бинарника сохраняет именно эту
версию std без зависимости от cwd или каталога исходников. Диагностика встроенной
копии показывает <std>/uart.he и исходные строки. В публичном Rust API Project можно
задать std_root для разработки либо предоставить named module texts; CLI использует
встроенную std. Сейчас в неё входит только uart.he с newline(), без строк.

Один .he-файл — один модуль. std::uart соответствует lib/std/uart.he.
Для приложения используется корень app: app::logging соответствует logging.he
относительно каталога входного файла. Корень std зарезервирован.
Обычный импорт модуля: import std::uart; он даёт квалифицированные имена, но не
активирует расширения. Пользовательское расширение подключается тем же способом:
import extension app::logging::UartTraceHelpers;

Первый вариант модулей: функции и расширения; пользовательские типы ещё не реализованы; без исполняемого top-level кода,
скрытых глобальных переменных, setup/loop и объявлений hardware в библиотеках.
Импортируемые файлы проверяются вместе с приложением, специализации создаются по
использованию. Стоимость неиспользуемых функций проверяется по итоговому ELF.
Циклические импорты отвергаются с показом цепочки. Package manager,
wildcard imports, re-export и отдельная компиляция пока не нужны.

## Следующее обсуждение: строки и массивы

Строки и массивы следует проектировать совместно, но реализовывать отдельными этапами.
Общие вопросы: длина, индексация, bounds checks, передача без копирования,
неизменяемость и различие Flash/SRAM. Текст дополнительно требует выбора кодировки
и определения единицы индексации. Не смешивать длину UTF-8 в байтах и число символов.

Первый пример расширения — newline, не требующий строк. Затем Flash-текст и
write_text/println. Фиксированные изменяемые массивы в SRAM, общие представления
последовательностей и интерфейс writer для обёрток обсуждаются явно; ни один из этих
механизмов не считается реализованным наличием UartTx-расширения.

## Внутренняя модель и границы

- DeviceKind::methods() — единый реестр встроенных методов по виду получателя,
  используемый при регистрации сигнатур и разрешении extension-вызовов. Расширение
  не может объявить встроенное имя даже с другой сигнатурой.
- modules.rs загружает граф исходников, modules/expand.rs разрешает имена и
  специализирует реальные AST функций по конкретным устройствам. Ни текстовая
  подстановка, ни runtime-передача адреса device не используются. Повторные вызовы
  одной специализации используют одну функцию. Исходные SourceLocation сохраняются.
- Все импортированные определения проверяются, включая неиспользованные static
  helpers. Для проверки их тел создаются экземпляры с абстрактными устройствами;
  они не попадают в hardware planning/IR/машинный код. Ограничения поддерживаемого
  подмножества также проверяются до их удаления. Это ограниченная специализация
  одного встроенного вида устройства, не общая система generics/traits.
- Обычный семантический анализ проверяет специализации, поэтому существующие
  noInterrupt, shared-access и blocking-контракты действуют через импортированные
  методы. Локальные extension-объявления активны в своём модуле. Приватные методы
  расширения доступны его реализации; внешние вызовы используют pub-методы.
- SourceLocation содержит идентификатор файла. Project.sources хранит оригинальные
  тексты; Diagnostic сохраняет source set для многофайлового вывода и byte spans,
  включая related labels в другом файле. Старые single-source API сохранены;
  app-импорты требуют Project с явным root или предоставленными module texts.
- Явные пределы первой реализации: глубина импорта/специализации 64, число экземпляров
  функций 4096. Превышение даёт диагностику. Выход filesystem-модуля за source root
  через symlink запрещён. Package manager и настройки проекта пока отсутствуют.
- Wrapper-структуры с исключительным владением остаются F15. Вызов метода/helper
  не передаёт владение и не создаёт второго владельца. Source-level override отсутствует.

Пример: examples/uart-extensions.he. Проверки: tests/extensions.rs и tests/cli.rs;
машинный сценарий проверяет std.newline в setup и ISR при LLVM none/speed/size.

## Результаты проверки

Полный gate: fmt, Clippy, 172 теста в debug и 172 в release, включая AVR8js.
Локальный журнал: build/extensions-full-gate-final.log (не коммитится).
`examples/uart-extensions.he`, 16 MHz, --opt size: 264 байта Flash и 1 байт
статической SRAM. HEX совпадает с эквивалентным примером прямых write_byte/flush
вызовов (build/extension-example.hex и build/extension-direct.hex). Максимальный
стек остаётся unknown; отсутствие накладных расходов подтверждено для этого
примера/режима, не обещается для любых функций. Плата не прошивалась.
